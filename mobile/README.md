# Strata 移动版规划（v0.1 · 2026-11-28）

> 本目录是 Strata 手机 / 平板版的落点。现在只有规划，没有代码；桌面版（v2.6.3）行为一行不改。
> 目的先说清楚：**移动版不是把 1440×900 的桌面窗口缩小，而是共用内核、重做一层壳。**

---

## 1. 结论先行

| 项 | 决定 |
|----|------|
| 复用范围 | `src/core`（文档 / 图层 / 选区 / 历史 / 变换）、`src/engine`（合成 / 滤镜 / 笔迹 / 编解码）、`src/i18n` **全部复用** |
| 不复用范围 | `src/ui/EditorShell.tsx`（550 KB 单文件）、菜单栏、双面板坞、右键体系、快捷键体系 |
| 交付形态 | 阶段一先出**浏览器可跑的移动布局（PWA）**，阶段二套 **Tauri 2 Android 原生壳** |
| 明确不选 | Capacitor（没有 Rust 侧解码，等于把 EXR / HEIC / RAW 显影 / TIFF16 全丢掉）；React Native / Flutter（内核是 DOM + Canvas + TypedArray，重写成本大于重做一遍） |
| iOS | 后置。需要 macOS 构建机（CI 的 `macos-latest` 或云 Mac），且 WKWebView 有两处硬差异，见 §7 |

一句话：**先证明"手机上这活儿能干"，再证明"手机上这活儿能装"。**

---

## 2. 现状盘点（为什么不能直接缩放）

- 桌面窗口 `minWidth: 1040 / minHeight: 680`，UI 结构是「菜单栏 + 左工具栏 + 右面板坞 + 状态栏」四边包围画布。
- `src` 共 286 个文件 / 3.98 MB；`ui` 目录 129 个文件，其中 `EditorShell.tsx` 550 KB。移动壳**不能** import 它。
- 交互全建立在键鼠上：24 个工具靠快捷键、27 种混合模式靠右键菜单、面板靠 hover、缩放靠 `ctrl+wheel` 与触控板 delta。
- Rust 侧不是外壳装饰，是主力解码链：EXR（`exr`）、HEIC（`heic-rs`）、JPEG（`zune-jpeg`）、RAW 真显影（`strata_raw/develop.rs`）、TIFF16 导出。**纯 Web 移动版会直接阉掉一半格式**，这也是必须带原生壳的原因。
- 好消息一：`engine/pen.ts` 本来就是按 Pointer Events 写的（pressure / tiltX / tiltY / pointerType），触控笔不用从零做。
- 好消息二：`engine/gpu/device.ts` 的 WebGPU 探测契约是「任何一步失败返回 null、绝不抛异常」，移动端天然能回退 Canvas2D。
- 好消息三：已有单文件 Web 构建（`vite.web.config.ts` → `dist-web/index.html`，1.8 MB），可作为移动壳的第一块地基。

## 3. 技术路线对比

| 方案 | 复用 Rust 解码 | 系统集成（文件关联 / 相册 / 分享） | 落地速度 | 结论 |
|------|----------------|-----------------------------------|----------|------|
| A. 纯 Web / PWA | ✗ | △（只能走浏览器下载与 File System Access，Android 支持很差） | 最快 | **只作为阶段一的验证载体** |
| B. Tauri 2 移动端（Android / iOS） | ✓ 同一个 `src-tauri` | ✓ | 中（要配 SDK/NDK） | **正式交付形态** |
| C. Capacitor | ✗ | ✓ | 中 | 不采用 |

Tauri 2 的做法不必新开一个壳工程：同一份 `src-tauri`，加一份 `tauri.mobile.conf.json` 覆盖 `productName`、`identifier`（`studio.xiaofang.strata.mobile`）、`frontendDist`（指向 `mobile/dist`）与 Android/iOS 段，命令形如 `tauri android build --config src-tauri/tauri.mobile.conf.json`。桌面 `npm run tauri:build` 完全不受影响。

## 4. 移动端信息架构

**唯一主体是画布，其余全部可收起。**

| 区域 | 手机（竖屏） | 平板（横屏） |
|------|--------------|--------------|
| 顶栏 | 返回 / 文件名 / 撤销重做 / 导出，高度 44，落在安全区内 | 同左，可加"另存为" |
| 画布 | 其余全部面积，`pointer-events` 独占 | 同左，左右各留一条窄轨 |
| 底部工具条 | 24 工具横向滑动分组（选择 / 画笔 / 修饰 / 变换 / 文字 / 视图），末位「更多」 | 双行或左轨竖排 |
| 面板 | 抽屉：图层、调整、历史、示波器，左/右边缘滑出或按钮唤出 | 常驻窄版右坞（≈280） |
| 属性条 | 当前工具参数浮在工具条上方，可上滑展开全参 | 同左，可钉住 |
| 菜单 | 取消菜单栏；「更多」里用分组列表（文件 / 编辑 / 图像 / 图层 / 滤镜 / 视图） | 同左 |

**手势表（必须一次定死，后面不再改）**

| 手势 | 行为 |
|------|------|
| 单指 / 笔 | 当前工具绘制（笔压、倾斜按 `pen.ts` 原逻辑） |
| 双指捏合 | 连续缩放（以两指中点为锚） |
| 双指平移 | 画布平移 |
| 双指旋转 | 画布旋转（可选，先关） |
| 双击画布 | 适配屏幕（100%） |
| 长按 400ms | 等同于桌面右键菜单 |
| 三指左滑 / 右滑 | 撤销 / 重做（可在设置里关） |
| 边缘 24px 内滑 | 唤出左 / 右抽屉 |
| 双指长按 | 吸管取色 |

**要让位的桌面习惯**：hover 预览 → 改成「选中后点一下才预览」；滚轮调数值 → 改成步进器 + 长按连加；快捷键 → 手势 + 设置里可选外接键盘映射（蓝牙键盘用户不少，映射表直接复用 `tools/catalog.ts`）。

## 5. 目录与代码组织

```
mobile/
  README.md                 本规划
  index.html                移动入口（viewport-fit=cover）
  vite.mobile.config.ts     移动构建（普通多文件产物，不做单文件内联）
  src/
    shell/                  移动壳：顶栏 / 工具条 / 抽屉 / 手势层
    viewport/               画布视口（若 EditorShell 内逻辑可抽出，见 §9 前置项）
    pages/                  开始页（最近文件 / 新建 / 关于）
  dist/                     构建产物（git 忽略）
```

约束三条，写进评审口径：

1. 移动壳只允许 `import` `src/core`、`src/engine`、`src/i18n`、`src/tools`，**禁止** import `src/ui/**`（含 `EditorShell`、`StartPage`）。
2. 共享层不改语义；确需改动的，先补单测再改，桌面版跑同一份单测。
3. 桌面 CSS 变量与主题 token 可复用（`src/styles`），但布局类名一律新建，避免两边互相污染。

## 7. 风险台账

| 风险 | 具体表现 | 对策 |
|------|----------|------|
| 内存 OOM | 手机 4–8GB，12MP 多图层 + 历史快照很容易炸 | 历史按字节计上限（默认 512MB）；图层超 20 个提示；大图走分块合成 |
| Safari 滤镜缺项 | `engine/filters.ts` 用了 `feConvolveMatrix`，Safari 不支持该原语 | 移动端统一走「Canvas 像素实现」分支，不依赖 SVG 滤镜；先做能力探测再选路 |
| WKWebView 无 WebGPU | iOS 26 之前没有 WebGPU | 直接走 Canvas2D 路径（`gpuBridge` 本来就允许回退），不做"假 GPU"提示 |
| Android 存储 | 分区存储限制任意路径写入 | 一律走 SAF / 系统文档选择器；`.strata` 只写用户选定目录 |
| 壳体重写走偏 | 有人图省事直接缩放桌面 UI | §5 第 1 条硬禁令 + Code Review 检查 import 白名单 |
| 桌面回归 | 抽 viewport 时改坏桌面渲染 | 抽取只许"搬家不改行为"，桌面跑同一套 `vitest` + 截图比对 |
| iOS 构建机 | 本机 Windows，无 Xcode | 走 CI `macos-latest`，或临时云 Mac；不排期到 P6 之前 |

## 8. MCP 在移动端怎么办

桌面的 MCP 是本地 Node 进程（`mcp/strata-mcp.mjs`），手机上跑不了 Node 常驻进程。三条路，P7 再定：

1. **明确不支持**（最省事，推荐先这样写进关于页）；
2. **手机连桌面**：桌面端开一个局域网 MCP 网关，手机只当客户端（安全要单独设计，别默认开）；
3. **云端**：不做，和「图片不上传」的底线冲突。

---

## 9. 前置项（P1 动手前必须先核实的两件事）

1. **画布渲染是否被焊在 `EditorShell.tsx` 里**。550 KB 单文件里大概率同时装着视口、笔迹调度、面板联动。P1 第一步是把它切成 `viewport`（纯渲染 + 纯指针处理，无 React 面板依赖），桌面改走新模块但行为不变。切不动就说明移动版要另写视口 —— 这决定 P1 是「大」还是「很大」。
2. **文档模型对触控的假设**。`core/document` 里的历史、选区、变换是否假设有键盘修饰键（shift 加选、alt 复制等）。若假设成立，移动端需要一套「模式开关」（选区加/减、复制/移动），在工具属性条里显式给按钮。

## 10. 本轮不做什么

- 不改桌面版任何布局、交互、打包流程；
- 不做账号、云同步、协作；
- 不做 iOS 的承诺排期；
- 不在 Windows 本机"看图说话"验收移动版 —— 浏览器设备模拟算 P1 验收，真机（至少一台 Android）才算 P2 之后验收。

## 12. 手机版功能分级（v1 到底承诺什么）

桌面 35 个工具、9 个分组全部可用，一次性搬上手机是必输的仗。手机版按「一条完整链路 + 能力分级」给承诺，不按「和桌面一样多」给承诺。

| 级别 | 工具 / 能力 | 说明 |
|------|-------------|------|
| **V1 必做（绘画底子）** | 移动、矩形/椭圆/套索/魔棒选区、画笔、铅笔、橡皮、油漆桶、裁剪、吸管、文字 | 这是绘画链的下限，不是全部；文字与裁剪同时也是修图要用的 |
| **V1 必做（修图闭环）** | 图层组 / 蒙版 / 剪贴、调整层（曲线 / 色阶 / 色彩平衡 / 可选颜色）、选区内调色、变换与裁剪 | 修图是一级能力，**不能用"调整层在 V1.5"糊过去**；没有它就没有第二条验收链路 |
| **V1 必做（精修工具）** | 仿制图章、修复画笔、模糊 / 锐化、减淡 / 加深 / 海绵、调整画笔、液化（基础推拉） | 这套是"专业 P 图但手边没电脑"的人真正要的东西，**不许押到 V1.5**；液化先给推拉与膨胀，重建 / 冻结后补 |
| **V1 手势替代** | 抓手、缩放 | 不做按钮，双指捏合/平移就是它们；这俩在手机上不存在"工具"概念 |
| **V1.5** | 涂抹、渐变、形状（含星形/柳叶笔）、标尺、计数 | 每个都要重排属性条，工作量按工具算，不打包 |
| **不做（长期也不做）** | 多标签页、示波器常驻、双面板坞、菜单栏、Droplet 批处理、插件宿主、快捷键循环 | 手机屏幕装不下，硬塞只会变成"能看不能用" |

两条附带决定：

1. **图层数上限**：V1 默认 20 层，超过弹提示并可"合并后继续"，不硬截断丢数据。
2. **工程格式不变**：仍是 `.strata` 单文件（JSON 清单 + 内嵌 PNG），手机版存的文件桌面版能直接开，反之亦然 —— 这是移动版唯一不能妥协的兼容项。

> 参照系说明：Photoshop 手机版并不是把桌面搬过去，而是另起一套界面 + 砍到子集 + 重度依赖云端；iPad 版做了多年也只追上部分桌面能力。所以"PS 都上手机了所以不难"是错觉，**难的是取舍，不是移植**。

## 13. 移动端对标（谁才是真正的对手）

结论：**不是 PS，也不止画世界 Pro。** 手机端用户按"任务"分流，不是一个软件通吃。按任务分三个对标位，各有各的学与不学。

| 对标位 | 参考产品 | 学什么 | 不学什么 |
|--------|----------|--------|----------|
| **绘画（并列一级）** | 画世界 Pro 手机版 | 手势（双指撤销、三指、掌拒）、悬浮调色盘、笔刷管理手势、图层缩略图手感 | 150+ 笔刷库、动画多轨、社区生态（短期打不过，也不该打） |
| **修图（并列一级）** | Lightroom 手机版 / Snapseed / PS 手机版 | 局部调整的遮罩交互、蒙版手势、曲线控点手感、相册直连 | 订阅墙、一键人像、"AI 魔法"式宣传；这些不是我们的卖点 |
| **专业手感（标杆）** | Procreate（iPad）/ 无限绘画 | 图层交互、指绘动力学、笔迹延迟控制、全屏无干扰 | 平台独占策略；iPad 专属的手势不必照搬到手机 |

**Strata 自己的位置**：手机上**唯一能打开 `.strata` / PSD 继续按图层改的地方**，中文、免费、不上传。差异化不在"再多一个画画软件"，而在"移动端最接近桌面的图层工作流"——图层组、蒙版、调整层、选区、非破坏编辑，这些是画世界 Pro 手机版最薄的一端，也是我们桌面已经做完的一端。

两条执行约束：

1. 现有 `docs/画世界Pro功能拆解-2026-11-25.md` 拆的是 **Windows 3.5.0 安装包**，不能直接当手机端依据。P1 之前另做一份《画世界 Pro 手机版实测》，只记屏幕布局、手势、笔刷管理与性能表现，不记参数猜测。
2. 对标验收用"任务"而不是"功能清单"：给同一张手机照片，要求 30 分钟内完成「抠主体 → 换背景 → 加字 → 导出」，和对手比步数与失败点，比数功能个数有用。

## 14. 产品定位：修图与绘画双一级，手机端不降级

> **勘误（v0.2）**：上一版这里写的是"手机版是绘画软件、修图降为辅助"，依据是"修图赛道没入口"。这条判断**作废**，两个原因：一，把"更牛逼的画世界 Pro"读成了"砍掉修图"；二，拿"一键出片的对手很多"去证明"精修没人要"，是拿错样本推结论。

**定位：修图和绘画在手机端仍然并列为一级能力，和桌面版一致。不砍、不降级、不改写。**

"更牛逼的画世界 Pro"的正确含义是：**绘画侧不比它弱；修图侧用桌面级的图层栈压过去**。画世界 Pro 本身就有滤镜、调色、变形、"内容编辑"，它不是纯画画软件，所以我们也不是"另一个它"。

先把修图用户拆开，别再混着说：

| 修图人群 | 典型动作 | 现有对手 | 我们的取舍 |
|----------|----------|----------|------------|
| 快修 | 一键人像、套滤镜、发圈 | 系统相册、醒图、美图 | **不做**，比不过，也没必要比 |
| 精修 | 分层修、局部调整、蒙版合成、抠图换背景、批次统一风格 | Lightroom 手机版、Snapseed、PS 手机版 | **做**，这是我们的主场：桌面已经做完的图层组、蒙版、31 种非破坏调整层、选区、变换 |

用户不按性别、不按"刷不刷手机"分，只按"要不要分层、要不要可回退"分。手机上有精修需求的人不少，缺的是能装进裤兜又不阉割图层的工具——这正是桌面版留下的空位。

由此定死：

| 项 | 承诺 |
|----|------|
| 一句话定位 | 手机上的修图与绘画工作站：能分层修、能画、能回桌面接着干 |
| **修图承诺** | 图层组 + 蒙版 + 剪贴蒙版；31 种非破坏调整层；曲线 / 色阶 / 色彩平衡；选区与抠图换背景；PSD 打开、`.strata` 双向互通 |
| **绘画承诺** | 笔压与倾斜跟手；画笔 / 铅笔 / 橡皮 / 油漆桶 / 涂抹；选区与变换；对称与参考图导入 |
| **两边都不承诺** | 一键人像、AI 抠图、滤镜商城、笔刷商城、动画多轨、社区 |

两条验收任务，缺一条都不算 V1 完成：

1. **修图链路**：一张手机照片 → 分层修（曲线 + 局部蒙版 + 换背景）→ 导出，全过程可回退。
2. **绘画链路**：空白画布 → 起草 → 上色 → 导出，笔迹不抖不飘。

## 15. 用户画像：手机上装 Strata 的是谁

不是"随手拍完套个滤镜"的人。会在手机上从 GitHub 找到这个仓库、再下载安装包的人，基本是这三类：

1. **有精修需求但没有电脑的人** —— 学生、宿舍没带台式机、公司电脑装不了软件、只租了工位；
2. **电脑不在身边的人** —— 出差、外拍、客户现场、通勤路上要改一版稿；
3. **用平板 / 手机当唯一生产力设备的人** —— 安卓平板接键盘鼠标，手机接手写笔。

共同点：**他们要的是"能把活儿干完"，不是"一键好看"。** 所以：

- 他们要图章、修复、加深减淡、液化、蒙版局部调整 —— 这些不是"专业版彩蛋"，是能不能交稿的问题；
- 他们能接受多两步操作，不能接受"改完不能回退""导出去丢图层"；
- 醒图那类工具卖模板与一键，卖点跟我们不重叠；我们卖的是"手机上也敢接商单"的完整度。

反过来说也成立：只想要一键美颜的人，装了 Strata 会觉得麻烦——这不是缺陷，是定位，别为了讨好他们去加模板中心。
