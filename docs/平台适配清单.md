# 三平台适配清单（2026-11-06）

> 硬约束：本机只有 Windows，**没有 Mac / Linux 测试机**（手机 Linux 装不了 Tauri 桌面运行时）。
> 所以这两个平台靠「CI 原生构建 + 严格静态检查」把风险前置拦截，用户最终真机点检兜底。

## 1. 打包现实
- Tauri 应用**不能跨平台交叉编译**：macOS 的 .app/.dmg 必须在 macOS + Xcode 上构建，
  Linux 的 deb/rpm/AppImage 必须在带 WebKitGTK 的 Linux 上构建。
- 本机 `npm run tauri:build` 只能出 Windows 包（nsis/msi）。
- 三平台包由 `.github/workflows/release.yml` 的 matrix 产出：
  `windows-latest` / `macos-latest` / `ubuntu-22.04`，
  手动 Run workflow 或 push `v*` 标签即触发，产物分别上传到三个 artifact。
- `tauri.conf.json` 本机只打 `nsis`（避免 Windows 上顺带打 MSI 触发 WiX 失败），CI 里按 matrix 用 `--bundles nsis / dmg,app / deb,appimage` 覆盖；
  图标 `icon.icns`（Mac）/ `icon.ico`（Win）/ png 全套已备齐。

## 2. 平台差异与应对

| 项 | Windows | macOS | Linux |
|---|---|---|---|
| 窗口 | decorations + transparent + Acrylic | `titleBarStyle: Overlay`、`hiddenTitle: true`：内容延伸进系统标题栏，红绿灯浮在左上；菜单栏 `padding-left: 80px` 避让，顶栏空白可拖窗 | 常规标题栏 |
| 玻璃 | WebView2 `backdrop-filter` 完整 | WKWebView 基本支持 | WebKitGTK 支持有限 → `--glass-blur: 10px` + tint 加浓降级，文字仍可读 |
| 窗口磨砂 | Rust 命令 `window_frost_acrylic` 直接调系统 Acrylic，**失败真返回**并浮出可见降级提示 | `setEffects(UnderWindowBackground)` + `EffectState.FollowsWindowActiveState`（NSVisualEffectView） | 官方明确 Unsupported：不调 API，直接降级并提示，改用「全局磨砂」 |
| 触控板 | Precision Touchpad：deltaMode=像素 → 平滑平移 + ctrl+wheel 捏合连续缩放（系数 0.0045） | 同为 Web 层 pinch/滚轮模型，捏合系数 0.0035；OS 已处理自然滚动方向 | 同 Web 层模型；行模式按 ×16px 换算 |
| 三指/四指手势 | Rust 原生阶段 2（未做） | Web 层无此概念 | 无 |
| 字体 | 微软雅黑 | 苹方（UI_FONT_STACKS 已含） | Noto / 思源（已含） |

## 3. 「一次成功」保障
- CI 每个 runner 都跑：tsc → vitest → `cargo test --lib` → tauri build；编译/打包不过直接红。
  Node 统一 22（Vite 7 要求 ≥20.19），`npm ci` 的 lock 已核对一致。
- 平台特定代码一律 `data-os` 前端分支 / `#[cfg(target_os)]` Rust 分支，默认路径安全。
- **本轮修掉的三个必炸点**（都是静态审查发现的，不是猜的）：
  1. `windows` crate（WIA 扫描）原先无门控挂在 `[dependencies]`，macOS / Linux 构建必失败；
     已移到 `[target.'cfg(windows)'.dependencies]`，`wia.rs` 的三个命令在非 Windows 上
     保留同名实现但明确返回「不支持」，不静默降级、不假装扫出图。
  2. `cargo test --lib` 原先因为 `testgen` 被 `#[cfg(feature = "testgen")]` 门控而编译失败
     （各解码器单测要 import 它），且缺 `image` 依赖；已改 `#[cfg(any(test, feature))]`
     并补 `[dev-dependencies] image`，**130 条 Rust 单测全过**。
  3. `core:window:allow-clear-effects` 在这个 Tauri 版本不存在（build script 直接拒绝）；
     `clearEffects` 与 `setEffects` 共用 `core:window:allow-set-effects`，权限清单保持四项。
- 配置：`tauri.conf.json` 的 macOS 段、Linux 依赖在 workflow 里显式安装。
- 未验证项（需用户真机）：Mac 顶栏红绿灯避让观感、Mac/Linux 玻璃观感、Acrylic 在 Windows 真机效果。

## 3.1 窗口磨砂为什么不再「点了没反应」
- Tauri 2.12 源码实证：`vibrancy::set_window_effects` 在 Windows 分支调用
  `window_vibrancy::apply_acrylic(...)` 后**丢弃 Result 并一律返回 `Ok(())`**，而且只采用
  `effects` 数组的第一个效果（写 `[Acrylic, Mica]` 并不构成兜底）。前端因此永远收不到
  「系统其实没采纳 Acrylic」这个事实 —— 这就是开关显示已开、窗口却不磨砂的根源。
- 现在 Windows 走自定义 Rust 命令，直接调 `window-vibrancy 0.8.1` 并把错误真返回；
  关闭时 `clear_acrylic` + `clear_mica` + `clear_blur` 一次清干净。
- `window-vibrancy` 只挂 `cfg(windows)` target，Mac / Linux 完全不编译它。
- Linux 的 `set_window_effects` 源码里两个平台分支都没有实现、直接 `Ok(())`（假成功），
  所以前端在 Linux 提前降级，根本不调用它。

## 4. 发布备注
- macOS 未签名包首次双击会被 Gatekeeper 拦（右键打开可绕）；正式发布需 Apple Developer 证书 + notarization（属发布流程，不影响构建成功）。
- Linux 包依赖 `libwebkit2gtk-4.1`，AppImage 自带依赖更省事。
