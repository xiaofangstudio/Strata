## 4. Windows 精准触控板 —— 实现方案（核心）

### 4.1 现状与缺口

当前 `EditorShell` 的输入处理：

| 输入 | 当前路径 | 问题 |
|---|---|---|
| 鼠标滚轮 | `wheel`（非 ctrl）→ 平移；`ctrl+wheel` → 离散缩放 | 能工作，但不区分鼠标/触控板 |
| 触控板两指滚动 | 走普通 `wheel`（deltaX/deltaY）→ 平移 | **能用**，但没用 `deltaMode` 识别为像素级平滑源，也没有 `getCoalescedEvents` 处理 120Hz 高频 |
| 触控板捏合缩放 | 走 `ctrl+wheel` → 缩放 | **不区分**触控板捏合 vs 鼠标 Ctrl+滚轮，易误触发；且 Chromium 捏合抖动未平滑 |
| 触控板双指旋转 | **无** | `pinchDelta.rotationDeg` 算了但没人消费 |
| 三指 / 四指手势 | **无**（Chromium 不转发给页面） | 必须走 Rust 原生才能拿 |
| 压力 / 接触面积 | **无** | 触控板 `POINTER_TOUCH_INFO` 带 pressure/contact，当前完全没用 |

**结论**：基础平移/缩放能用，但「精准」二字没做到 —— 缺设备识别、缺像素级/高频优化、缺旋转、缺高阶手势。

### 4.2 三条技术路径对比

| 路径 | 做法 | 覆盖能力 | 成本/风险 | 跨平台 |
|---|---|---|---|---|
| **A. 纯 Web 层优化** | 在现有 `wheel`/`pointer` 处理上加 `deltaMode` 识别、`getCoalescedEvents`、触控板捏合平滑、双指旋转消费、`maxTouchPoints` 辅助区分 | 两指平滑平移、捏合缩放、双指旋转、惯性 | 低；不需 Rust；但拿不到三指/四指手势、拿不到原始压力/接触面积 | ✅ 自动跨平台（Win/Mac/Linux 都走同一 Web 事件模型） |
| **B. Rust 原生 WM_POINTER** | `src-tauri` 用 `windows` crate subclass WebView2 HWND，拦截 `WM_POINTER*` 拿 `POINTER_TOUCH_INFO`（pressure/contact/位置），自算多指距离/角度，经 Tauri event 发给前端 | 三指/四指手势、原始压力、更稳的捏合（独立于 ctrl+wheel 抖动） | 高；Windows-only；需谨慎 swallow 消息避免与 WebView2 自身手势冲突；`cfg(windows)` 包裹 | ❌ Windows-only，需保证其它平台编译不崩 |
| **C. 混合（推荐）** | A 先做满（覆盖 90% 用户），B 作为 Windows 增强叠加（三指/四指/压力） | 全部 | 中 | A 跨平台 + B Windows 增强 |

### 4.3 推荐：分阶段混合（C）

- **阶段 1（必做，纯 Web）**：设备识别 + 像素级平滑平移 + 捏合缩放去抖 + 双指旋转 + 惯性。零 Rust 改动，立即提升「精准」体感。
- **阶段 2（Windows 增强，Rust）**：原生 `WM_POINTER` 监听，提供三指/四指手势动作（如三指切工具、四指适应屏幕）、把触控压力/接触面积作为可选的笔刷压力源。通过 Tauri event 桥接。

### 4.4 阶段 1 —— Web 层具体设计

文件：`src/ui/EditorShell.tsx`（现有 `wheel` 监听，约 1150 行附近）+ 复用 `src/engine/motion.ts`。

1. **设备来源识别**
   - `e.deltaMode === WheelEvent.DOM_DELTA_PIXEL (0)` → 触控板/现代鼠标（平滑像素增量）；`DOM_DELTA_LINE (1)`/`PAGE (2)` → 老鼠标（离散行，缩放用固定步长）。
   - 捏合判定：`e.ctrlKey && e.deltaMode === 0` 视为触控板捏合；鼠标 `Ctrl+滚轮` 多为 `deltaMode === 1`，借此区分，再用 `navigator.maxTouchPoints > 0` 辅助。
   - 维护一个 `inputSourceRef`（`mouse`/`trackpad`/`pen`/`touch`），由最近事件推断，供后续逻辑（如是否加惯性）使用。

2. **像素级平滑平移（触控板两指）**
   - 普通 `wheel`（`deltaMode===0`，无 ctrl）：`setPan` 直接累加 `deltaX/deltaY`（已是像素级，无需再乘系数）；用 `getCoalescedEvents()` 展开高频事件，避免丢帧。
   - Windows 触控板 OS 已处理「自然滚动」方向，JS 拿到的即正确方向，**不要**再硬编码反向（与 macOS 不同，文档写清）。提供 `touchpadNaturalScroll` 偏好（默认跟随/开）允许用户反选。

3. **捏合缩放去抖**
   - `ctrl+wheel`（触控板捏合）：把 `deltaY` 映射为 `scale` 增量，喂给现有 `zoomLiveRef` 缓动缩放（本轮已有），而非离散跳变；做一次指数平滑（`scaleNext = scale * exp(-deltaY * k)`）。
   - 检测「手势结束」：连续 `wheel` 间隔 > 100ms 视为结束，停止平滑、固化到 state（避免与 OS 惯性叠加成双重缩放）。

4. **双指旋转（新增）**
   - 在现有 `pointerType==="touch"` 的 pinch 分支（行 3228–3254）消费 `pinchDelta(...).rotationDeg`：把两指夹角变化映射到 **视图旋转**（`rotateDocumentArbitrary` 风格）或自由变换旋转（按当前工具）；加一个小阈值（< 0.5° 忽略）防抖。

5. **惯性**
   - 触控板 OS 级惯性已发一串衰减 wheel，直接消费即可；若叠加本轮 `flickGlide`，需在「手势结束」判定后只跑一次，避免双重惯性。

### 4.5 阶段 2 —— Rust 原生增强设计

新建 `src-tauri/src/touchpad.rs`（Windows-only，`cfg(windows)`）。

1. **子类和监听**
   - 通过 `tauri::Manager` 拿 `WebviewWindow` → `hwnd()`；用 `windows` crate 的 `SetWindowSubclass` 挂自定义 `SUBCLASSPROC`。
   - 处理 `WM_POINTERDOWN/UPDATE/UP`：`GetPointerInfo` 拿 `POINTER_INFO`（pointerType、`PT_TOUCH`=2 即触控；精准触控板在 Windows 10+ 也走 `WM_POINTER` 而非旧 `WM_GESTURE`）。
   - 维护活跃 touch 指针集合（`HashMap<pointerId, POINTER_TOUCH_INFO>`）。

2. **多指几何 → 事件**
   - 2 指：算两指中心距离/夹角变化 → emit `touchpad-pinch`（payload: `{scale, rotationDeg, centerX, centerY}`），前端据此做缩放+旋转（比 ctrl+wheel 更准、不抖）。
   - 3 指：emit `touchpad-swipe3`（payload: 方向/矢量）→ 前端映射为「切换上一/下一工具」或「撤销/重做」（待定，需用户拍板）。
   - 4 指：emit `touchpad-swipe4` → 「适应屏幕 / 显示全部」。
   - 单指压力/接触面积：`POINTER_TOUCH_INFO.pressure`（0..1024）、`rcContact` → emit `touchpad-pressure`（可选，作为笔刷压力源之一）。

3. **消息处理谨慎性**
   - 对捏合相关 `WM_POINTER` 在 subclass 里返回 `0`（已处理），阻止 WebView2 自身也缩放页面；其余 `CallWindowProc` 原链，不破坏文本选择等。
   - 全部 `cfg(windows)` 包裹；非 Windows 构建跳过，保证 `cargo check` 不崩。

4. **依赖**
   - `Cargo.toml` 加 `windows = { version = "0.58", features = ["Win32_UI_WindowsAndMessaging","Win32_Graphics_Gdi","Win32_Foundation"] }`，核对不顶高 MSRV 1.77；保留既有许可证来源声明习惯。

### 4.8 风险 / 回退 / 验收

- **风险**：① Rust subclass 与 WebView2 自身手势冲突（捏合被双重消费）→ 退路：只 emit 不 swallow，前端用 `maxTouchPoints` 去重。② `windows` crate 版本顶高 MSRV → 锁定 0.58 并 `cargo check`。③ Tauri event 高频（120Hz 多指）造成前端负担 → 前端做节流/RAF 合帧。
- **回退**：阶段 2 若 subclass 不稳定，可先只发 `touchpad-pressure`（低风险），手势动作延后。阶段 1 是纯 Web、零风险，必上。
- **验收**：
  1. 触控板两指平移丝滑无阶梯（像素级）。
  2. 触控板捏合缩放不会被鼠标 Ctrl+滚轮误触发。
  3. 双指旋转视图生效（新增）。
  4. 三指/四指手势（Windows 真机，阶段 2）。
  5. 鼠标滚轮/笔/触屏行为不被破坏（回归）。
  6. 非 Windows 平台编译通过、功能静默降级。
