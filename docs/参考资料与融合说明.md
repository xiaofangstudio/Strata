# Strata 参考资料与融合说明

> 日期：2026-10-17
> 适用对象：接手 Strata 的开发/设计同学
> 一句话：`Compositor` 是合成内核蓝本，`MyPaint` 是绘画蓝本，`PhotoCraft` 是 PS 级功能与 PSD 蓝本；三者都只「看思路」，不搬代码。PhotoCraft 的 Windows 便携版已落地并建好快捷方式。

---

## 一、先看结论

1. **PhotoCraft 0.9.0 Windows 便携版已安装到位**，快捷方式在 Strata 根目录，双击即可对照它的真实界面与操作。
2. **Strata 内部没有值得删的重复文件**：全量扫描 5913 个文件，重复仅 36 组、合计 0.45MB，全部是 MyPaint 便携运行时和 Tauri 图标自带的多份副本，删了会破坏程序，保持原样。
3. **下载用的 zip 已删除**（79.3MB，与解压后的内容完全重复），只保留可执行目录。
4. **PhotoCraft 不能直接拼进 Strata**：它是纯 Rust + egui + wgpu 的原生应用，Strata 是 Tauri v2 + React/TS 前端 + Rust 内核。两者只能做「模块对照 + 按思路重写」。
5. **融合优先顺序**：界面交互补齐 → 文档/图层模型升级 → PSD 读写 → 色彩管理 → 滤镜与绘画 → RAW/HEIC。

## 三、四个参考物：各是什么、能拿什么、不能拿什么

| 参考物 | 来源 / 许可 | 它在 Strata 里的角色 | 可以拿 | 绝对不拿 |
| --- | --- | --- | --- | --- |
| `Compositor/` | macOS 开源项目，**MIT** | 合成、图层、调整层、PSD、Camera Raw 的**内核蓝本** | 架构划分、算法思路、参数组织、面板结构 | 任何一行 C/Swift/Metal 代码 |
| `MyPaint/` | MyPaint 2.0.1，**GPL 系** | 绘画引擎与笔刷手感的**交互蓝本** | 笔刷手感目标、工具栏组织、快捷键习惯 | 任何代码（GPL 会传染 MIT 项目） |
| `reference/artcraft-photocraft/` | storytold/photocraft，**MIT OR Apache-2.0** | PS 级功能的**模块地图**与 PSD/RAW/矢量/文字的**实现路线** | 模块边界、数据结构设计、算法步骤、测试用例思路 | 任何代码（项目铁律：从零自研） |
| `PhotoCraft/`（便携版） | 同上，v0.9.0 | **可运行对照物**：真实界面、真实手感、真实导出结果 | 观察交互、对比像素结果、记录行为差异 | 反编译、抄资源、直接把 exe 塞进安装包 |

> 许可说明：Compositor 与 PhotoCraft 的许可都允许在保留声明的前提下复用代码，但 **Strata 的铁律是「从零自研，不复制任何一行」**。所以本项目的做法统一为：读实现 → 写自己的模块 → 用测试对齐行为。MyPaint 是 GPL，连「参考后改写」都要谨慎，只取交互层结论。

## 四、PhotoCraft 的模块地图（24 个 crate）

源码在 `reference/artcraft-photocraft/crates/`，对照关系如下（右侧是 Strata 的落点）：

| PhotoCraft crate | 职责 | Strata 落点 |
| --- | --- | --- |
| `psd` | PSD(v1)/PSB(v2) 无损读写 | 新建 `src-tauri/src/psd/`，目前 Strata **完全缺失** |
| `io` | 文档与 PSD/平坦格式互转 | `src-tauri/src/io/` + `src/engine/project` |
| `cms` | 纯 Rust ICC v2/v4：解析、写入、变换、黑点补偿 | 新建 `src-tauri/src/color/icc.rs`，目前只有 sRGB 8 位 |
| `color` | 色彩模型与位深 | `src/engine/image`、`src/core/document` |
| `raster` | 光栅表面、tile、通道 | `src/engine/raster`、`src/engine/surface` |
| `geom` | 几何与变换 | `src/core/transform` |
| `doc` | 文档/图层/蒙版/通道模型 | `src/core/document`、`src/core/layer` |
| `ops` | 编辑命令与撤销栈 | `src/core/history`、`src/core/layerOps` |
| `compose` | 图层合成、混合 | `src/engine/compositor`、`src/engine/blend` |
| `gpu` | wgpu 合成器（Metal/Vulkan/DX12/WebGPU） | `shaders/*.wgsl` + WebGPU 合成路径 |
| `paint` | 画笔、笔刷动力学 | `src/engine/paint`、`shaders/brush.wgsl` |
| `algo` | tile-aware CPU 滤镜：模糊、锐化、噪声、扭曲、风格化 | `src/engine/filters`、`src/engine/retouch` |
| `vector` | 矢量路径、形状层、矢量蒙版、描边 | **缺口**：先做路径对象，再接形状层 |
| `text` | 字体库、排版（parley）、文本层光栅化 | **缺口**：现在文字是一次性栅格化 |
| `raw` | 纯 Rust 相机 RAW 解码与显影（DNG/CR2/TIFF-EP） | **缺口**：Camera Raw 面板与显影链路 |
| `heif` | HEIC/HEIF 静态图解码（heic-rs 包装） | **缺口**：`src/engine/image` 扩解码器 |
| `codecs` | 平坦格式对称编解码，保留位深与元数据 | `src/engine/image`、`src/engine/tiff` |
| `format` | 自有工程格式：manifest + 内容寻址 zstd tile | 对照设计 `.strata` 工程格式 |
| `affinity` | Affinity 原生文档读取 | 暂不需要 |
| `plugins` | WASM 沙箱滤镜插件（wasmi） | 暂不需要（与 ≤100MB、自研优先冲突） |
| `automation` | 引擎上的 MCP 服务与 GUI 桥 | 可借鉴思路，不引入 |
| `tablet` | 数位板压感/倾斜（macOS/Linux） | Windows 需另做（`src/ui/pointer`） |
| `engine` | 应用级编排 | 对照 `src-tauri/src/lib.rs` 与前端 store |
| `ui-egui` | egui 界面 | **只看面板组织与交互流程**，不搬代码 |
| `testkit` | 测试工具 | 参考测试组织方式 |

## 五、为什么不能直接融合（技术事实）

| 维度 | Strata | PhotoCraft |
| --- | --- | --- |
| 应用形态 | Tauri v2 桌面壳 + WebView | 纯 Rust 原生窗口 |
| 界面 | React 19 + TypeScript + CSS | egui（立即模式 GUI） |
| 渲染 | WebGPU 优先、WebGL2 回退，WGSL | wgpu，原生 Metal/Vulkan/DX12 |
| 内核 | Rust（编解码、滤镜、合成） | Rust（24 个 crate 全量实现） |
| 工程格式 | `.strata`（文件夹 + manifest） | `.pcraft`（manifest + zstd tile） |
| 安装包 | 目标 ≤100MB | 仅主 exe 就 102.7MB |

两边语言都是 Rust，但 **UI 层与渲染接入方式完全不同**；直接把 PhotoCraft 的 crate 拖进 `src-tauri` 会造成依赖体系、线程模型、窗口模型三处冲突，且违反「从零自研」。

正确姿势：

- **UI/交互**：开 `PhotoCraft.lnk` 实际操作，记录「点哪里、出什么面板、参数顺序是什么」，回到 React 里重写。
- **算法/数据结构**：读 `reference/artcraft-photocraft/crates/<模块>` 的公开接口与测试，理解步骤后在自己的模块实现，用像素对比验证。
- **不可替代的参考价值**：PSD 的图层/通道/文本/矢量结构、ICC 变换链、RAW 显影步骤、矢量蒙版与文字排版——这四块是 Strata 目前最缺、而 PhotoCraft 写得最完整的部分。

## 六、融合路线（按依赖顺序）

### 第 1 步：界面与交互补齐（不改内核）
- 图层面板：拖拽重排/嵌套、右键菜单、Option 拖拽复制。
- 变换：数值输入面板、方向键微调。
- 选区：多边形套索、移动并复制、图层/蒙版载入为选区。
- 参考 `PhotoCraft` 的实际操作路径与 `ui-egui` 的面板组织，但视觉规范仍以 Strata 的交接文档为准（左侧 30+ 工具、右侧单列标签、`Ctrl+K` 命令面板）。

### 第 2 步：文档与图层模型升级（融合的地基）
- 图层携带非破坏变换参数，合成时才光栅化。
- 引入**矢量形状层**与**可编辑文本层**（PhotoCraft 的 `vector` / `text` 是路线参考）。
- 蒙版独立变换与链接。
- 这一步不做，后面的 PSD、钢笔、文字都接不上。

### 第 3 步：PSD / PSB 读写
- 先读后写：读入时按「像素层 → 组 → 蒙版 → 调整层 → 图层样式 → 文本 → 矢量」分级支持。
- 写出时优先保证 PS 能无损打开：通道、混合模式、蒙版、调整层。
- 对照物：`crates/psd` + `crates/io`；验收方式是同一 PSD 在 PhotoCraft 与 Strata 里逐层对比。

### 第 4 步：色彩管理
- ICC 解析/变换/渲染意图/黑点补偿（对照 `crates/cms`）。
- 文档位深从固定 8 位扩到 8/16 位，颜色模型作为运行时数据。
- 这是 Camera Raw 与专业输出的前置条件。

### 第 5 步：滤镜、绘画与矢量/文字
- 把 `algo` 的 tile-aware 滤镜思路落到 `src/engine/filters`（模糊族、锐化、降噪、扭曲、风格化）。
- 画笔动力学与数位板压感（Windows 端自研）。
- 矢量路径：锚点/控制柄、路径转选区/蒙版/形状、路径描边。
- 文字：框内多行、字距行距、实时改字、可当剪贴蒙版。

### 第 6 步：RAW 与 HEIC（体积敏感，最后做）
- RAW 解码 + 显影面板（光效、颜色、曲线、混色器、颜色分级、细节、光学、几何）。
- HEIC 解码。
- 必须做体积评估：参考版仅主 exe 就 102.7MB，Strata 的红线是安装包 ≤100MB，因此这两块要么做成可选组件，要么只保留精简解码路径。

## 七、红线与已知冲突

1. **无 AI**：PhotoCraft 的 Quick Selection、Object Selection、Select Subject、Remove Background 一律不移植。Strata 只做确定性算法：魔棒、套索、色彩范围、扩展/收缩/羽化、内容感知填充（PatchMatch 类，不含模型）。
2. **≤100MB**：RAW、HEIC、ICC、字体都可能撑爆体积。每加一个解码器都要先量体积。
3. **不复制代码**：Compositor（MIT）、PhotoCraft（MIT/Apache）只做思路参考；MyPaint（GPL）连改写都要避免。
4. **全中文、Windows 优先、MIT、永久免费**：参考物不得改变这四条。
5. **发布前必删**：`reference/`、`Compositor/`、`MyPaint/`、`PhotoCraft/`、`PhotoCraft.lnk`，以及 `docs/` 里暴露内部参考路径的内容（按需）。
