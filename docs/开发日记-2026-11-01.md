## 一、上午：启动意图分离（真 bug 修复）

**问题**：双击图片「用 Strata 打开」会先闪欢迎页，参数读不到就停在欢迎页，像没生效。

**根因**：`App.tsx` 的渲染判定是「有文档就进编辑器，否则渲染欢迎页」，而「打开启动文件」
藏在欢迎页的 `useEffect` 里 —— 欢迎页永远抢跑，失败还无声。

**改动**：
- 内核新增 `launch_intent` 命令，在 Rust 里直接判好 `{kind: "file"|"home", path}`；
- 加 `tauri-plugin-single-instance`：软件开着时再双击图片，路径经 `strata://launch-open`
  事件转发给已有窗口，不再另起进程；
- `core/launch.ts`（意图判定）+ `engine/openFile.ts`（打开文件→文档，两条来路共用）+
  `BootScreen`（启动占位 / 失败屏，失败有声）；
- `fileAssociations` 补上图片扩展名与 `.strata-droplet`。

## 三、File 组最后 7 项（全部是真功能，不是占位）

### 1. 打开 EXR Parts —— `exr` crate（纯 Rust，BSD-3）
- 新命令 `exr_part_info`（列部件：名字 / 尺寸 / 通道）与 `exr_read_all`（逐部件解码）。
- HDR → LDR 是真实有损转换：线性值经 **sRGB 伽马编码**、超亮裁白、Alpha 保持线性。
- 前端 `ExrDialog` 勾选部件 → 每部件一层。
- **验证**：`src-tauri/tests/exr_roundtrip.rs` —— crate 自己写再走同一条解码路径读回，
  锁坐标映射与 sRGB 编码。
- 版本注意：`exr 1.74.2` 要 rustc 1.83，按工程 MSRV 1.77 锁 `1.74.0`。

### 2. 渲染视频 —— 纯 TS GIF89a + LZW 编码器（`engine/gif.ts`）
- 不引 ffmpeg（几十到一百多 MB，必碰 100MB 体积红线）。视频图层的帧序列逐帧
  按图层栈合成 → 中位切分量化（复用 `medianCutPalette`）→ GIF 导出，透明区垫白。
- **今天的头号大坑：GIF-LZW 码长增长时机**。我最初按「分配后自增，`next === 2^n` 就加长」
  实现（A 规则），测试解码器镜像了同一个错误，往返自测全绿 —— 但 **PIL 一开就报
  broken data stream**。写了个三变体对照（A/B/C）让 PIL 裁决：标准行为是
  **「刚分配出去的码顶满 2^codeSize 就立刻加长，然后才轮到下一个号」**（B 规则）。
  教训：**自洽 ≠ 合规，编码器必须拿真实世界的解码器对账**。测试文件里带了一个完整的
  GIF-LZW 解码器做逐位往返验证。
- 前端「渲染视频」弹窗：缩放 + 最长边上限，导出循环播放的 GIF。

### 3. 浏览（Bridge 式）—— 新命令 `list_dir`
- `BrowseDialog`：选文件夹 → 网格卡片（子文件夹可逐级下钻 + 图片缩略图串行解码），
  点图片走与双击完全相同的 `openFileToDoc` 通路进编辑器。
- `list_dir` 对单个子项读失败是跳过不是整体报错（几万文件的目录里个别文件被占用是常态）。

### 4. 创建 Droplet —— `.strata-droplet` 配方文件
- PS 的 Droplet 是个小程序；Strata 的等价物是**配方文件**：`core/recipe.ts` 定义
  「自动对比度 / 转灰度 / 限长边 / 导出 PNG / 导出 JPG」五种真实操作，
  `parseRecipe` 做严格校验（不认识的 op 直接拒绝，绝不带病运行）。
- 双击配方文件 → 内核 `launch_intent` 认出 → App 进入 `DropletRunner`
  （选导出文件夹 → 拖图 / 选图 → 逐张处理导出，逐条报成功失败）。
- **拖放注意**：Tauri v2 里 HTML5 drop 拿不到路径，必须走
  `getCurrentWebview().onDragDropEvent`（开始页面早就有这个惯例）。

### 5. 脚本事件管理器 —— 事件挂配方
- 事件（打开文档 / 新建文档）→ 配方，存 localStorage；`App.openDoc` 是全应用唯一的
  文档入口漏斗，事件配方在那里真实执行（带 `sourcePath` 视为「打开」，否则「新建」）。
- **如实声明**：导出事件暂不支持 —— 导出入口分散在多条链路上，挂错会静默吞图，宁缺毋滥。
- 没有脚本运行时（rhai 之类）也是如实声明的：动作就是这五种配方的固定序列。

### 6. WIA 扫描 —— 真实的 Windows 图像采集 COM
- `windows` crate（0.62）`Win32::Devices::ImageAcquisition`，`IWiaDevMgr2::GetImageDlg`
  一步到位：设备选择 + 厂商扫描界面都是系统的，扫完落盘再对比文件夹快照找出新文件。
- **CLSID 怎么拿**：windows crate 没生成 `CLSID_WiaDevMgr2` 常量，SDK 头文件里也只有
  接口 GUID；最后**直接查本机注册表** `HKCR\WIA.DeviceManager\CLSID` →
  `{E1C5D730-7E97-4D8A-9E42-BBAE87C2059F}`。
- 无设备时枚举数为 0，前端如实告知「先接好设备装驱动」，不假装扫出图。
- 工程细节：Tauri 的 `HWND` 与 windows crate 的 `HWND` 是两个类型且不带 `Send`，
  跨线程前降成 `isize` 传递。

### 7. 路径到 Illustrator —— Alpha 轮廓描迹（`core/tracePath.ts`）
- Strata 没有矢量路径对象（一直如实声明），但「把剪影交给 AI 继续加工」可以真做：
  marching-squares 边沿法逐像素发有向边（不透明区在左侧）→ 链成闭合环 →
  共线合并 → SVG（`fill-rule="evenodd"`，洞自动镂空），Illustrator 可直接打开。
- `.ai` 是 Adobe 私有格式，界面原话说明「Strata 不冒充」。
- 测试锁：矩形合并成 4 角、3×3 环出内外两环、分离块各自成环、阈值行为。

## 六、中午追加：Ctrl+Z 覆盖修复

**用户反馈**：Ctrl+Z 对很多东西不生效 —— 这是最常用的键，必须覆盖所有操作。

**真因**（比"某些操作没进历史"更隐蔽）：`EditorShell` 的全局 keydown 里有一句
`if (el.tagName === "INPUT") return`，一刀切把所有输入控件排除了。拖完滑杆焦点还在
`input[type=range]` 上，**Ctrl+Z 被整个吞掉** —— 用户眼里就是"撤销对很多操作无效"。

**改法**：
- 只有「真在打字」的控件才让路：TEXTAREA / contentEditable / type=text|search|url|email|password|tel；
- range / checkbox / radio / number / button 一律交给应用撤销栈；
- Z / Y 的处理提到输入框判断**之前**（最常用的键不该被控件劫持）。

顺带发现 `History.commit` **不去重**，于是滑杆"松手就提交"会往撤销栈里塞无变化的假步骤，
按 Ctrl+Z 看着像没反应 —— 已在调色台里加「值没变就不落库」的闸门。

## 七、下午：调色台（对齐达芬奇 Resolve 的 Color 页）

**需求**：像达芬奇那样一体化调色，而不是散在一堆对话框里。

**落点**（用户让我自己挑位置）：右侧停靠坞新增 **「调色台」面板**，图标排在示波器上方 ——
达芬奇也是把工具放左边、示波器放右边，这里同理：调色台与「示波器」面板上下相邻。
窗口菜单也加了「调色台」开关。

**为什么做成调整层**：新增 `AdjustId = "grade"`，进 `PIXEL_ADJUST_IDS`，由合成器逐像素调用
`applyGrade`。于是它天然是**非破坏**的（只作用于下方已合成画面）、可混色/带蒙版、
随文档保存，并且每次落库都进撤销栈 —— 刚修好的 Ctrl+Z 直接覆盖。

**四页**（对应截图里的四块）：
| 页 | 内容 |
|---|---|
| 一级 | 色温 / 色调 / 对比度 / 轴心 / 中间调对比；暗部 Lift、中间调 Gamma、亮部 Gain（各分 RGB）；阴影 / 高光 / 饱和 / 色相 / 黑场偏移 |
| 色轮 | 暗部 Dark / 阴影 Shadow / 亮部 Light / 全局 Global 四个色轮（拖动偏色、双击归零）+ 每档曝光 / 饱和 |
| 切片器 | 红 / 皮肤 / 黄 / 绿 / 青 / 蓝 / 品红 七段色相，各自色相 / 饱和 / 亮度 —— 只动该色域 |
| 曲线 | RGB 复合 + 分通道，单击加点、拖动改形、双击删点 |

**内核设计**：凡只跟单像素自身值有关的部分（白平衡、LGG、对比度、曲线）预先烘成
三张 256 项 LUT，逐像素只查表；只有需要亮度/色相上下文的（阴影高光、色轮分档、
切片器、全局饱和）才走逐像素分支。中性参数逐字节恒等（有测试锁死）。

**验证**：`tests/unit/grading.test.ts` 19 条 —— 冷暖方向、Lift 抬黑、Gain 只动亮部、
Gamma 只动中间调、对比度绕轴心不动、饱和归零变灰、色相 +120° 红转绿、色轮按亮度分档、
切片器只碰目标色相、透明像素不被上色、以及与调整层体系的接缝（56 个参数、默认中性）。
全量 **38 文件 / 589 条全过**。
