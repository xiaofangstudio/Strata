# Strata · 参考蓝本内核清单

> **小方工作室 · 内部** ｜ 文档版本 `v1` ｜ 2026-10-06 ｜ 面向：M0 之后的逐个落地，M1 / M2 编码时对照使用

---

## 一、这份清单做什么

把 `Compositor\`（参考蓝本）里**真正值得看的计算内核**逐个过一遍，回答三个问题：它做什么、我们能参考到什么程度、我们的对应实现落在哪个模块与哪个里程碑。

**铁律边界（先看这条）**：`Compositor` 是 MIT 协议，法律上允许复用其代码；但本项目的铁律 2 自设了更严的标准——**不复制任何一行代码，只借鉴架构与算法思路，实现全部自研**。所以下文的"可直译"指的是**按同一思路自己重写**，不是拷贝。本文档按此口径编写。

## 二、盘点范围与总体结论

| 类别 | 规模 | 可参考程度 |
|------|------|-----------|
| 9 个 C 内核 | 约 2083 行（含头文件） | **可参考程度最高**——纯 C99，只 `#include <math.h>/<stdlib.h>/<string.h>/<float.h>/<stdint.h>/<stddef.h>` |
| 4 段 MSL 计算内核 | 约 930 行（内嵌在 Swift 字符串里） | **可参考程度高**——MSL 与 WGSL 语义接近，算法可直译 |
| 217 个 Swift 文件（约 4.5 万行） | 全量 | **仅借结构**——SwiftUI / AppKit / Metal / CoreImage / Vision 绑定，Windows 上无从复用 |

**两条实测修正**（与现有文档记载不符，建议后续更正）：

1. `立项规划书.md` §5.3 写「9 个 C 文件（**SSE/NEON 向量化**）」——**实测不成立**。9 个 `.c` 里没有任何 SIMD 指令，全是标量 C 循环，向量化交给编译器自动完成。我们的 Rust 版因此**不必先啃 SIMD**，普通循环 + `rayon` 并行即可起步。
2. `DitherPixels.c` 是 9 个内核里**唯一带平台依赖**的——用了 Apple GCD 的 `dispatch_apply`（1 处，按行分带并行）。其余 8 个零平台依赖，可原样对照重写。

> 另有一条重要空白：**混合模式公式不在参考里**。`SeparableBlend.swift` 把 Color Burn / Linear Burn / Vivid Light / Hard Mix 等直接委托给 CoreImage 的 `CIFilter`，公式并未落在仓库中。P0 的「PS 全套混合模式」必须按 PS 的公开公式**自研**，不能指望参考。

**贯穿全部内核的一条共同约定**（值得直接继承）：所有像素内核都是**语言无关的纯函数**——入参是「预乘 RGBA8、每像素 4 字节、按行 `stride`」的裸内存 + 尺寸，无全局状态、无单例、无框架类型。我们的 Rust 内核照此办理：`&mut [u8]` + `stride` + 尺寸，`rayon` 在外层切带并行，便于单测与跨语言验证。

## 四、9 个 C 内核逐条

### 1. `LevelsPixels.c`（60 行）— 色阶 · 分类 A

导出三个函数：`levels_apply`（按 256 项查找表套用）、`levels_histogram`（统计直方图，支持 coverage 掩膜）、`cube_apply`（维度 N 的 3D LUT 立方体查找）。

**可参考的点**：查表式色阶的实现骨架，以及「直方图带 coverage 掩膜」这一细节（统计时只算选区内的像素，PS 的手感就来自这里）。`cube_apply` 顺带覆盖了 3D LUT，Camera Raw 与后续 LUT 支持能直接用。

**我们怎么做**：Rust 侧纯查表 + `rayon` 分带；同时提供 WGSL 版供实时预览。P0 的「色阶（含自动）」直接落在这里。

---

### 2. `NoisePixels.c`（45 行）— 添加杂色 · 分类 A

`noise_add` / `noise_add_at`。`amount` 用 PS 的百分比口径（均匀噪声跨 ±amount% 半程，高斯噪声标准差取其三分之二）；支持单色（三通道加同一个值）；**每个像素的噪声只由位置与 `seed` 决定**，所以同 `seed` 同位置必得同颗粒。

**可参考的点**：那套「位置 + seed 决定值」的确定性噪声，是后续「胶片颗粒」「修复画笔的纹理模式」共用的基础工具。`_at` 变体带 `origin_x/origin_y`，让同一张图被切成不同分块渲染时颗粒仍然连续对齐——这个坑我们一定会遇到，提前采用。

---

### 3. `LensPixels.c`（36 行）— 镜头畸变 · 分类 A

`lens_distort`：对每个目标像素，按它相对中心、以半对角线归一化的半径 `r`，以 `(1 - k·r²)` 缩放采样点，源图做双线性采样，越界透明。`k > 0` 收（矫正桶形），`k < 0` 放（矫正枕形），`k = 0` 原样复制。

**可参考的点**：只有 36 行，却是《滤镜库》里「镜头校正」的数学核心，`AdjustPixels.h` 的 `adjust_camera_raw_optics` 也复用同一 `distortionK`。Rust 版照做即可，注意与 GPU 版参数语义保持一致。

---

### 4. `BrushPixels.c`（48 行）— alpha 工具 · 分类 A

四个小工具：`brush_alpha_bounds`（非零 alpha 的半开边界，用于脏矩形）、`layer_extract_alpha`（抽 alpha 成灰度图，即蒙版）、`layer_unpremultiply_opaque`（反预乘）、`layer_restore_alpha`（回填 alpha）。

**可参考的点**：这是「图层蒙版」与「脏矩形失效」的地基。把 alpha 抽成灰度位图、再把 alpha 回填，正是蒙版编辑的往返路径；`*_bounds` 则是 §6.2「分块 + 脏矩形」需要的边界计算。P0 的图层与 P1 的蒙版都会用到。

---

### 5. `WandPixels.c`（195 行）— 魔棒 / 色彩范围 / 轮廓 · 分类 A + B

三个函数：`wand_mask`（魔棒，参考色为 seed 周围 `(2r+1)²` 方块均值，逐通道含 alpha 比对，`contiguous` 走 4 连通洪水填充）、`color_range_mask`（色彩范围，含 include / exclude 两组色与 fuzziness）、`wand_trace`（把掩膜的边界追成**闭合环**，外环顺时针、内环逆时针，正好对应扫描线填充的绕数规则）。

**可参考的点**：`wand_trace` 是**蚂蚁线**的关键——它输出的角点环可以直接喂给 Web 端做选区虚线动画，不用在 GPU 里重算轮廓。返回 `-2`（轮廓过于细碎不值得画）这个分支也值得学。

**分类拆分**：魔棒与色彩范围是 **A**（算法清楚，BFS + 容差）；轮廓追踪偏 **B**（绕数与环的合并需要自己重新组织数据结构）。P0 的魔棒 / 按色选区落在这里。

---

### 6. `ContentFill.c`（92 行）— 内容识别填充 · 分类 B

`content_fill`：先取掩膜边界，用一个 **LCG 伪随机**（`state * 1664525 + 1013904223`，这是个凭空写死的常量，供"填充质量"与颗粒方向取舍）做**补丁匹配**，再做传播与随机搜索。

**可参考的点**：这是「确定性算法做内容感知」的完整示范——**不含任何机器学习**，正好是 §十二「无 AI」立场下「生成式填充 → 内容识别填充」的落点。92 行很短，算法路径清楚，可按同一思路在 Rust 重写。

**注意**：参考版是简化版 patch match，填充效果有上限；我们的 P1 版本可以在同一骨架上加强（多尺度搜索、更好的边界融合），但**必须保持确定性**，不得引入模型。

---

### 7. `DitherPixels.c`（354 行）— 抖动 · 分类 B

`dither_apply`（11 种风格：Atkinson / Floyd-Steinberg / Bayer 2·4·8 / 网点 / 线 / 菱形 / 图案 / 字形 / 扫描线）、`dither_dots`（按 `block` 把像素压成圆点）、`dither_glow`（叠加辉光）。

`DitherParams` 参数面很宽：色调档数（2–8）、扩散量、密度与对比、网屏角度、亮暗反转、是否保留原色、明暗双色、字形覆盖率图与排列、扫描线的断点与摆动。

**可参考的点**：这是「导出抖动 / 降色」的完整参数设计，同时把「错误扩散」「有序抖动」「半调」三族算法压缩在一处，可当参数与交互的参照。

**为什么是 B**：算法本身不复杂，但 11 种风格各自的常量表（Bayer 矩阵、字形图）与参数组合需要成套重排；`dispatch_apply` 那处 GCD 并行换成 `rayon` 即可。属于 P3 打磨项，不急。

---

### 8. `HealPixels.c`（249 行）— 污点修复 · 分类 B

`heal_coverage_bounds` + `spot_heal`，三种模式：**0 内容感知**（复制周围环带最匹配的邻近补丁）、**1 创建纹理**（从边缘平滑填充 + 按周围细节补颗粒）、**2 邻近匹配**（取最近的好补丁）。复制来的纹理用**膜填充（membrane fill）**沿边缘差异平滑铺开，按 `coverage × opacity` 替换原像素。

**可参考的点**：三模式的分工与「膜填充让补丁与周边色调严丝合缝」的做法，是 P1「修复画笔 / 污点修复」的直接蓝本；同样是**确定性算法**，落在「无 AI」允许范围内。

**为什么是 B**：需要配套的补丁搜索半径、环带匹配代价、膜求解器——数据结构要按我们的像素管线重排，工作量中等偏大。

---

### 9. `AdjustPixels.c`（1104 行）— 调整 + Camera Raw 全组 · 分类 B（分阶段）

最大的一块，17 个导出函数，基本是一个完整的 Camera Raw 算法库：

| 组 | 函数 | 我们对应 | 里程碑 |
|----|------|---------|--------|

| 晕影 | `adjust_colored_vignette`（按画面框造型，含 Highlight Priority） | `adjust/vignette.rs` | P2 |
| Camera Raw 光效/颜色 | `adjust_camera_raw`（白平衡三增益、曝光、对比、高光、阴影、白、黑、自然饱和度、饱和度；含高光/阴影溢出预览） | `adjust/camera_raw.rs` | P2 |

## 五、4 段 MSL 计算内核

这 4 段都是内嵌在 Swift 源文件字符串里的 MSL，编译期由 Metal 编译器直接吃；**算法与平台无关，可直译 WGSL**。`texture2d` / `device` / `thread_position_in_grid` 分别对应 WGSL 的 `texture_2d` / `storage` / `global_invocation_id`；`float4`、`mix`、`clamp`、`sample` 语义基本相同。

### 10. `MetalBrushCoverage.swift`（153 行）— 连续笔迹覆盖率 · 分类 A ★最高价值

内核 `continuousBrush`。核心思路（**这是绘画线最该学的一段**）：

- **按行进距离积分沉积，而不是按指针事件数或样条细分段数**。长而稀疏的事件与短而密集的事件，出来的覆盖完全一致——这正是很多自研画笔「画快了变淡、画慢了变浓」的病根。
- **光学密度可加，覆盖 = `1 - exp(-density)`**。即 source-over 软笔尖在固定间距下的连续形式。
- 段内积分用**八点 Gauss-Legendre 求积**，且裁剪到笔尖支撑范围内。
- 硬边（`hardness ≥ 1`）走另支：直接取最小距离 + 像素边缘抗锯齿，不做密度累加。
- **永久笔迹与可替换的 tail 严格分离**：tail 只进预览、绝不累加进永久像素（自交处也不例外）。这正是 §6.5「绘制层：笔迹先画在 GPU 覆盖层，抬笔再提交」的算法化表达。

**我们怎么做**：`shaders/brush.wgsl` 里按同一思路重写，配合 §6.5 的三层缓解方案。P0 起就按这个模型设计画笔，比先做「一堆 dab 叠加」再返工划算得多。

---

### 11. `GPUNoise.swift`（158 行）— 噪点 / 颗粒（GPU） · 分类 A

内核 `add_noise`、`add_grain`，辅助函数 `mix32` / `unit` / `lattice` / `grain_field`。

**可参考的点**：`mix32` 这类整数散列是 GPU 上**确定性噪声**的通行做法——同一坐标同一 seed 必得同值，与我们第 2 条 CPU 版 NoisePixels 的确定性要求一致。CPU / GPU 两版并存时，务必统一散列口径，否则预览与导出会出现细微色差。

---

### 12. `MetalLayerEffects.swift`（379 行）— 图层样式 · 分类 B

九个内核：`effects_alpha`（抽 alpha）、`effects_spread_rows` / `effects_spread_columns`（行/列方向膨胀收缩）、`effects_ring`（取环带）、`effects_shift`（位移）、`effects_blur_rows` / `effects_blur_columns`（可分离高斯模糊两趟）、`effects_inside`（内描边判定）、`effects_compose`（按像素合成）。

**可参考的点**：把「描边 / 投影 / 內阴影 / 外发光 / 内发光」统一拆成**形状生成 + 可分离模糊 + 合成**三步，是我们 P1 图层样式的直接参考。可分离模糊拆成 rows / columns 两趟也是 GPU 标准做法，WGSL 照搬结构。

**为什么是 B**：形状生成与合成的像素规则需要按我们的混合模型与蒙版语义重排，不能照抄参数。

---

### 13. `MetalWarp.swift`（240 行）— 涂抹 + 液化 · 分类 B

五个内核：`warp_pick_up`（拾取笔刷携带色）、`warp_smudge`（涂抹，携带色与当前色按笔压混合，且**每次只携带刚留下的、不含更早的**）、`warp_copy` / `warp_clear`（区域拷贝与清零）、`warp_push`（前向 warp：笔刷下的像素跟着笔走，中心最多、边缘归零，权重是 `t²(3-2t)` 的 smoothstep）。

**最值得学的一点**：**液化不重采样像素**——它维护一张**逐像素位移场贴图**，每个 dab 只改位移场，像素始终从未被动过的原图按位移采样一次。这样液化后边缘**保持锐利**；若每步重采样像素本身，就会越涂越糊（参考注释里明确记了这条教训）。

**为什么是 B**：位移场纹理、scratch 缓冲与 dab 的 barrier 时序需要按我们的管线重排。P2 的涂抹、P3 的液化。

## 六、参考里没有、必须自研的部分

| 项 | 情况 | 影响 |
|----|------|------|
| **混合模式公式** | `SeparableBlend.swift` 把 Color Burn / Linear Burn / Vivid Light / Hard Mix 等直接委托 CoreImage `CIFilter`，公式不在仓库中 | P0 的「PS 全套混合模式（按 PS 顺序）」**必须自研**，按 PS 公开公式实现并写往返测试。这是 P0 最需要预留工期的项 |

## 七、落地顺序建议（与 §十 里程碑对齐）

1. **P0 必做的内核**：`LevelsPixels`（色阶）、`BrushPixels`（alpha 工具）、`WandPixels`（魔棒）、`rgba_clamp_premultiplied`（重采样夹制）、`continuousBrush`（画笔模型）。外加**自研混合模式**。
2. **P1**：`HealPixels`（修复）、`ContentFill`（内容识别填充）、`MetalLayerEffects`（图层样式）、`AdjustPixels` 的基础调整组。
3. **P2**：`AdjustPixels` 的 Camera Raw 全组、`GPUNoise` / `NoisePixels`、`LensPixels`、`MetalWarp` 的涂抹。
4. **P3**：`DitherPixels`、`MetalWarp` 的液化。

每个内核落地时**先写 Rust 单测（或 WGSL 对照用例）再写实现**——参考版都是纯函数，正好可以用同一组输入输出做基准对照（用于验证，不用于拷贝）。
