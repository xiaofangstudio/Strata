# 剩余 7 项：依赖选型与落地路径

> 2026-10-31 整理。剩下的 7 条菜单项都要「外部能力」（编解码器 / 硬件 / 脚本运行时），
> 纯前端做不了。这份文档把每个方向**可用的成熟库**列清楚：仓库地址、crate 名、许可证、
> 体积、形态（Rust crate / 独立二进制 / WASM）、接入位置，以及已知坑。
>
> 原则：**能用 Rust crate 就不引二进制**（二进制要处理平台分发与体积）；
> 只有 ffmpeg 这种「自己编一遍要几小时」的才用 sidecar。

---

## 一、Open EXR Parts（读 .exr 分层）

| 项 | 内容 |
|---|---|
| 推荐 | **`exrs`** — https://github.com/johannesvollmer/exrs |
| crate | `exr`（当前 1.74.x） |
| 许可证 | BSD-3-Clause |
| 体积 | 编译后约 240 KiB，纯 Rust，**零 unsafe**，不需要 CMake |
| 能力 | 读取 multi-part（多图层）、多分辨率、任意通道（rgb/xyz/depth/motion…）、16f/32f/u32 |
| 压缩支持 | 无压缩、ZIP、RLE、**PIZ**、PXR24、B44/B44A |
| 不支持 | **DWAA / DWAB**（有损小波，影视常用）、Deep Data |
| 官方替代 | OpenEXR 官方 Rust 绑定（要编译 C++）—— 兼容性最全，但违背「零 C++ 构建」 |

**接入路线**

1. `src-tauri/Cargo.toml` 加 `exr = "1.74"`。
2. 新增 Tauri 命令 `read_exr_parts(path) -> Vec<{ name, width, height, rgba }>`：
   用 `read_all_data_from_file` 拿到图层列表，每个 layer 转 RGBA8（HDR 值先做
   简单 tonemap 或直接 clamp，由前端给参数）。
3. 前端：`文件 > 打开 EXR 部件` 弹一个「选哪个部件」的列表，选中后走现有
   `docFromBitmap` 建文档，其余部件各建一层。

**坑**
- DWAA/DWAB 文件会报错 —— UI 里要明确说「这个压缩算法不支持」。
- 32f 数据转 8 位会丢动态范围；建议同时提供「按曝光 tonemap」选项（我们已有 `previewTone`）。

## 二、Render Video（把视频图层的帧渲染成视频）

| 项 | 内容 |
|---|---|
| 推荐 | **ffmpeg sidecar**（Tauri 官方 External Binaries 机制） |
| 仓库 | https://github.com/FFmpeg/FFmpeg （构建建议用 gyan.dev 的 Windows 静态版） |
| 许可证 | **LGPL/GPL**（用 `--enable-gpl` 的构建是 GPL）—— 分发要遵守，注意合规 |
| 体积 | 静态单文件 **约 80–150 MB**（这是主要代价） |
| 备选（纯 Rust，体积小） | `rav1e`（AV1，BSD）或 `x264` 绑定；**GIF** 用 `gif` crate（MIT，约 30 KB） |

**接入路线（sidecar）**

1. 下载静态 ffmpeg，按 Tauri 规则命名放 `src-tauri/binaries/`：
   `ffmpeg-x86_64-pc-windows-msvc.exe`（用 `rustc -vV | grep host` 确认 target triple）。
2. `tauri.conf.json`：
   ```json
   { "bundle": { "externalBin": ["binaries/ffmpeg"] } }
   ```
3. `capabilities/default.json` 加权限：
   ```json
   { "identifier": "shell:allow-execute",
     "allow": [{ "name": "binaries/ffmpeg", "sidecar": true, "args": true }] }
   ```
4. 前端：视频图层的帧序列 → 逐帧写临时 PNG → 调
   `ffmpeg -framerate 24 -i frame_%04d.png -c:v libx264 -pix_fmt yuv420p out.mp4`。

**折中方案（更省事）**：先用 `gif` crate 做 **GIF 导出**（纯 Rust、几十 KB、
不需要 ffmpeg），把「Render Video」变成「导出 GIF 动画」，并在菜单里注明。
等真的需要 mp4 再接 sidecar。

## 三、WIA Support（Windows 扫描仪）

| 项 | 内容 |
|---|---|
| 推荐 | **`windows` crate**（microsoft/windows-rs）直接调 WIA COM 接口 |
| 仓库 | https://github.com/microsoft/windows-rs |
| 许可证 | MIT OR Apache-2.0 |
| 平台 | **仅 Windows**（Linux 用 SANE、macOS 用 ImageCaptureCore，本项目先只做 Windows） |
| 备选 | `nokhwa`（相机采集，**不是扫描仪**，别选错） |

**接入路线**

1. `[target.'cfg(windows)'.dependencies] windows = { version = "0.6x", features = ["Win32_Devices_ImageAcquisition", "Win32_System_Com"] }`
2. 命令 `list_scanners()`：`CoCreateInstance(WIA.DeviceManager)` → `DeviceInfos` 枚举。
3. 命令 `scan(device_id, dpi, color_mode)`：`CommonDialog.ShowSelectDevice` 或直接
   `CreateDevice` → `Item.Transfer(format)` → 拿 `IWiaItem2` 的位图字节并落成 PNG。
4. 前端：`文件 > 导入 > WIA 支持` → 选设备 → 扫描 → 作为新文档打开。

**坑**：WIA 是 COM，必须 `CoInitializeEx`（Tauri 主线程已初始化，工作线程要自己来）；
扫描设备可能很慢，命令要异步 + 进度事件。

## 四、脚本运行时（Droplet / Script Events Manager / Browse / Batch）

| 项 | 内容 |
|---|---|
| 推荐 | **`rhai`** — https://github.com/rhaiscript/rhai |
| 许可证 | Apache-2.0 OR MIT（双许可，选 Apache-2.0 走） |
| 体量 | 5.7k stars，v1.24.0（2026-01），活跃；纯 Rust、可 no_std、可 WASM |
| 为什么是它 | 专为「嵌进 Rust 程序」设计：注册函数即 API，沙箱可控（能限操作数/超时/内存） |

**接入路线**

```rust
// 把编辑器能力注册成脚本函数
let mut engine = Engine::new();
engine.set_max_operations(500_000);      // 防止死循环
engine.register_fn("open", |p: &str| ...);
engine.register_fn("resize", |w: i64, h: i64| ...);
engine.register_fn("export", |p: &str| ...);
```

- **Batch / Droplet**：脚本 = 一段 rhai，作用对象 = 一批文件。Droplet 的
  「拖文件到图标上」用文件关联（Tauri 的 `open` 事件 + 一个 `.strata-droplet` 扩展名）。
- **Script Events Manager**：事件名（`onOpen` / `onSave` / `onExport`）→ 脚本路径的映射表，
  存在偏好里，主流程在对应时机 `eval` 一次。
- **Browse**：不需要库 —— 用官方 **`tauri-plugin-fs`**（https://github.com/tauri-apps/plugins-workspace）
  的 `readDir` 做目录树，前端渲染即可。

**坑**：脚本能读写文件 = 安全面变大。默认禁用文件系统函数，只在用户显式开启
「危险模式」时注册。

## 五、Paths to Illustrator（把路径导出成 .ai/.svg）

我们现在**没有矢量路径对象**（选区、蒙版、字形轮廓最终都落成像素），所以这条要么
补一个矢量模型，要么**先把像素矢量化**。

| 项 | 内容 |
|---|---|
| 推荐 | **`vtracer`**（visioncortex） |
| 仓库 | https://github.com/visioncortex/vtracer |
| 许可证 | MIT（或 MIT OR Apache-2.0） |
| 体量 | **7.3k stars**，活跃（2026-10 有提交），纯 Rust crate + CLI + WASM |
| 特点 | 唯一能处理**彩色**的成熟方案；分层堆叠而不是挖洞，SVG 更紧凑；O(n) 拟合 |
| 备选 | `img2svg`（色彩量化 + Potrace 风格，但很新，0.1.x）；`potrace` 只支持黑白 |

**接入路线**

1. 用户选中一块区域（选区或图层）→ 取 RGBA → `vtracer::convert_image_to_svg`。
2. 按 `colormode`（color/bw）+ `mode`（pixel/polygon/spline）+ `filter_speckle` 出 SVG。
3. 写盘为 `.svg`（Illustrator 可直接打开），或直接读回成我们的形状层。

**顺带的好处**：这条路打通后，「转换为形状」「定义自定形状」也能变成真矢量，
而不是现在这种「轮廓描边成像素」的近似。

## 零、先看两个硬约束（核对完仓库现状后补的）

1. **项目有 100MB 体积红线**
   `src-tauri/Cargo.toml` 里写着「体积红线 ≤ 100MB：发布版优先体积」，当前安装包 **2.1MB**。
   把 ffmpeg 静态版打进包里（80–150MB）会**直接破线**。所以视频渲染只能二选一：
   - **GIF 优先**（`gif` crate，纯 Rust，几十 KB）—— 推荐先做这个；
   - mp4 走**运行时可选**：菜单里让用户指定/下载 ffmpeg，不进安装包。
2. **MSRV 是 Rust 1.77**
   引依赖前先核一遍要的版本：`cargo add exr rhai vtracer --dry-run` 看会不会把
   rust-version 顶高。顶了就锁到支持 1.77 的旧版本（`exr = "=1.73"` 之类）。

3. 现有插件只有 `tauri-plugin-dialog` + `tauri-plugin-opener`。
   「Browse」需要的目录枚举要么加 `tauri-plugin-fs`，要么直接在 Rust 侧写个
   `read_dir` 命令（后者更轻，不用再加插件）。

```bash
# 目录：vendor/（不进 git，或按需 submodule）
git clone --depth 1 https://github.com/johannesvollmer/exrs        vendor/exrs        # EXR
git clone --depth 1 https://github.com/visioncortex/vtracer        vendor/vtracer     # 矢量化
git clone --depth 1 https://github.com/rhaiscript/rhai             vendor/rhai        # 脚本
git clone --depth 1 https://github.com/microsoft/windows-rs        vendor/windows-rs  # WIA

# 二进制（不进 git）
# 1) ffmpeg 静态版：https://www.gyan.dev/ffmpeg/builds/
#    → src-tauri/binaries/ffmpeg-x86_64-pc-windows-msvc.exe
```

> 实际上大部分不需要克隆源码：`cargo add exr`、`cargo add vtracer`、`cargo add rhai`
> 就够了（Cargo 自己拉）。**只有 ffmpeg 必须手动下二进制**。

## 建议的实施顺序

| 顺序 | 项 | 理由 | 预估 |
|---|---|---|---|
| 1 | **EXR** | 纯 crate、无体积代价、立刻可用 | 半天 |
| 2 | **矢量化（Paths to AI）** | 顺手把「转换为形状」也变成真矢量 | 一天 |
| 3 | **脚本（rhai）** | 一次解决 Batch/Droplet/事件管理器 3 项 | 一天半 |
| 4 | **WIA** | 只影响 Windows，且要用真机测 | 一天 |
| 5 | **视频渲染** | 体积决策（GIF 先上 / ffmpeg 后接），最费事 | 看选哪条 |

**体积影响预估（对照 100MB 红线）**

- 只加 EXR + 矢量化 + 脚本：安装包约 **+2 MB** → 4MB 左右，红线内 ✅
- 加 WIA：**+0.3 MB** ✅
- 加 ffmpeg sidecar：**+80~150 MB** → **破线** ❌
  所以 mp4 只能做成「运行时外挂」：用户自己指定 ffmpeg 路径，
  或者首次使用时下载到 `%LOCALAPPDATA%`，不进安装包。

**第一步（明天可以直接跑的验证）**

```bash
cd src-tauri
cargo add exr --dry-run      # 看 MSRV 与依赖树是否可接受
cargo add rhai --dry-run
cargo add vtracer --dry-run
```

三个都能装的话，就先按「EXR → 矢量化 → 脚本」的顺序做，全部是纯 Rust，
不碰打包链路，安装包体积也在红线内。
