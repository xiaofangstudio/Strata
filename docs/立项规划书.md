## 一、项目定位

### 1.1 一句话定位

> **一个为中文用户从零打造、Windows 优先、永久免费开源、轻量（≤100MB）、无 AI 的图像编辑器 —— 平替 Photoshop。**

### 1.2 我们解决什么

| 痛点 | 现状 | 我们的答案 |
|------|------|-----------|
| **贵** | Photoshop 订阅制，年费上千 | **永久免费 + 开源（MIT）**，绝不做收费 / 会员 / 广告 |
| **不顺手** | GIMP 交互逻辑和 PS 差太远，用惯了 PS 的人迁移成本高 | **PS 级交互与快捷键**，肌肉记忆直接迁移 |
| **不在 Windows / 没有中文** | Compositor 只支持 macOS 26 + Apple 芯片，且**完全没有汉化** | **Windows 原生优先 + 中文原生**（不是汉化包，是天生中文） |
| **工具笨重** | PS 本体数 GB，装完占用十几 GB | **安装包 ≤ 100MB**（实测约 10–20MB），轻量、启动快、干净 |
| **AI 黑箱 / 隐私顾虑** | 越来越多软件内置 AI，动不动上传图片 | **完全无 AI**：算法全部确定性、可解释，图片不出本机 |

### 1.3 明确不做的事（边界）

- ❌ **不做任何 AI / 机器学习功能**（抠图、去背景、生成式填充、自然语言改图、超分等一律不做）
- ❌ 不做在线版 / 云端协作（先做单机桌面，**图片不出本机**）
- ❌ 不做 3D、视频剪辑、动画时间轴（另一个品类）
- ❌ 不追求「像素级复刻 PS 的每一个菜单」（要的是**工作流等价**，不是功能清单堆砌）
- ❌ **不 fork、不套壳、不抄 Compositor 的代码**（参考设计与逻辑，实现全部自研）
- ❌ **不做任何商业化**（无付费墙、无会员、无广告、无数据上报）
- ❌ **不做体积失控**：不引入任何会显著膨胀安装包的捆绑运行时

### 1.4 能力定位：修图与绘画并列一级

Strata 同时是修图软件与绘画软件，两条线都按一级能力（Level-1）打磨，不存在「主功能 + 附带涂鸦」的关系。

| 方向 | 定位 | 一级标准（必须达到） | 判定口径 |
|------|------|---------------------|---------|
| 修图 | 完整后期工作流 | 色阶（含自动）、曲线、色相饱和度、亮度对比度、色彩平衡、可选颜色；图层、蒙版、剪贴蒙版、调整图层、图层样式；魔棒 / 色彩范围 / 快速选择、修复画笔、污点修复、仿制图章、内容识别填充；ICC 色彩管理与 16 位/通道精度 | 单张照片从导入到出图的全流程可在 Strata 内完成，中途无需换软件 |
| 绘画 | 面向创作 | 压感画笔（压力 / 倾斜）、笔刷引擎与预设库、笔尖稳定与抖动修正、色混合 / 湿边、对称与参考线、高刷新率下的低延迟绘制 | 长时间绘画的笔感与延迟达到可用标准（见 §6.5） |

若任一方向被砍到「只能画笔 + 简单叠图层」，那它本就是「画世界」一类应用已有的能力，产品也就失去存在理由。因此色阶、曲线、蒙版、调整图层这些修图基础能力归入 P0 / P1，不得延后到 P3。

两条线都能做满，靠的是同一套核心：文档模型、图层与合成、颜色管线、文件 IO、输入与撤销。核心只实现一次，修图与绘画各自在其上叠加工具层，工作量不因「双方向」而翻倍。

绘画线唯一的高风险项是 WebView2 下的笔迹延迟，处理方案见 §6.5；修图线不涉及该风险。

## 二、为什么做（背景）

1. **Compositor 给了信心，也留了空位。** 它证明了「一个人 + 开源 + AI 辅助」也能做出 PS 级的东西（7.7k star，MIT 协议，图层 / 蒙版 / 调整图层 / Camera Raw / PSD 读写一应俱全）。但硬伤是：**只跑 macOS 26 + Apple 芯片，且一个中文字符都没有**。
2. **Windows + 中文 = 巨大的空白。** 国内绝大多数设计 / 电商 / 自媒体用户是 Windows，中文界面是刚需；现有方案要么是昂贵的 PS，要么是半汉化 / 老版本。
3. **移植不可行，但重写可行。** 已实测：把 Compositor 移植到 Windows **不可行**——它是 SwiftUI + AppKit + Metal + Vision 全家桶（217 个 Swift 文件、4.5 万行），这些框架在 Windows 上没有对应物，**本质是重写而非移植**。既然都要重写，那就**从零写一个更干净的**。
4. **低依赖是可达的。** Compositor 的 `Package.resolved` 里**只有一个第三方库**（Sparkle，自动更新），其余全是系统框架与 9 个自研 C 内核——证明「自包含、少依赖」完全做得到，我们照这个标准来。
5. **轻量是选型的硬约束。** 用户提出安装包体积的**硬性红线**（初版 30MB，后放宽至 **≤100MB**）。即便如此，Electron（自带整个 Chromium，最低 60MB+）也不是好选择，仍然指向 **Tauri v2**：复用系统 WebView2（Win10/11 普遍预装），把体积压到十几 MB，同时 Rust 内核比 Node 更适合做图像计算。

> **不借鉴**：Swift / SwiftUI 的具体实现与 Mac 专属 API（在 Windows 上无从复用）。

### 4.3 逻辑骨架：9 个自研 C 内核

| 内核 | 职责 | 我们对应的自研模块（Rust） |
|------|------|--------------------------|
| `AdjustPixels.c` | 色调 / 明暗调整 | 调整层 shader / Rust 算子 |
| `LevelsPixels.c` | 色阶 | 色阶 / 曲线 shader |
| `BrushPixels.c` | 画笔落笔 | 画笔引擎（GPU） |
| `HealPixels.c` | 修复画笔 | 修复 / 污点工具 |
| `ContentFill.c` | 内容识别填充 | 内容识别填充（**确定性算法**，非 AI） |
| `LensPixels.c` | 镜头校正 | 镜头校正滤镜 |
| `NoisePixels.c` | 噪点 | 添加杂色 |
| `DitherPixels.c` | 抖动 | 降色 / 导出抖动 |
| `WandPixels.c` | 魔棒选区 | 魔棒 / 按色选区 |

> **借鉴**：把**重计算拆成独立、可测试、语言无关的内核**这一架构——我们的对应物是 **Rust 内核模块 + WebGPU compute**，同样独立、可单测。
> ⚠️ 注意：Compositor 的 `ContentFill.c` 与 `WandPixels.c` 都是**确定性算法**（非机器学习），因此**不在「去 AI」的删除范围内**，照做。

### 4.4 工程格式：`.comp` 的设计（值得照抄思路 → 我们的 `.strata`）

`Compositor` 的 `.comp` = 一个**文件夹**，内为 `manifest.json` + `images/<图层UUID>.png`。

**设计精髓（我们要全盘继承）：**

- **非破坏**：图层像素与变换**分开存**，变换不烧进像素，随时可改；
- **明文可读**：manifest 是 JSON，**脚本能直接生成与修改**；
- **显式校验 + 版本演进**：schema 已迭代到 **v11**，每一版都明确「旧版读不了就拒绝」，绝不误渲染；有像素上限（单边 3 万 px、合计 1 亿 px、1 万图层）等硬性防护；
- **原子保存**：协调式原子替换，避免半保存损坏。

> **我们的对应**：沿用**同一思路**（文件夹 + manifest + PNG 图层，扩展名 `.strata`），并在 v1 就引入**显式校验 + 版本号 + 往返测试**。

> **参考它的「骨」（功能划分、UI 骨架、格式设计、逻辑架构），自研它的「肉」（每一行实现）。**

## 五、底层框架映射（macOS → Windows → 我们实际用什么）

> 三层对照：**Compositor 用什么 → Windows 原生对应什么 → 我们实际采用什么**。

### 5.1 图形与图像

| 能力 | Compositor（macOS） | Windows 原生对应 | 我们实际采用 | 许可 |
|------|--------------------|-----------------|-------------|------|
| 2D 矢量 / 位图渲染 | CoreGraphics（Quartz 2D） | **Direct2D** | WebView2 画布 + **WebGPU/WebGL2**；矢量走 **`resvg`/`usvg`**（Rust） | MPL-2.0 |
| 图像滤镜管线 | CoreImage | **Direct2D Effects + WIC** | **Rust 内核多线程（`rayon`）** + WebGPU compute | MIT |
| GPU 图形与计算 | Metal | **Direct3D 12** | **WebGPU**（Windows 上底层即 D3D12），回退 **WebGL2** | W3C / Khronos |
| 数值 / 向量加速 | Accelerate（vImage/BLAS/vDSP） | DirectML / Intel oneAPI | **Rust 原生 SIMD**（`std::simd` / `wide`） + `rayon` 多线程 | MIT/Apache |
| 文字排版与字形 | CoreText | **DirectWrite** | UI 文字走 WebView2；画布栅格化走 **`cosmic-text` + `rustybuzz`** | MIT |
| 图像编解码 | ImageIO | **WIC** | **Rust `image` crate**（+ `libheif-rs` / RAW 解码） | MIT/Apache（详见 §5.4） |
| 文件类型识别 | UniformTypeIdentifiers（UTI） | 无 UTI 等价 → MIME + 注册表关联 | **`infer`**（Rust，magic number 探测） | MIT |

> **已移除**：原「计算机视觉（Vision → Windows ML → onnxruntime）」一行，因**本项目不引入 AI**，整条链路取消（见 §十二）。

### 5.3 SIMD 内核 → 我们的承载方式

| 项 | 方案 |
|----|------|
| 原内核 | 9 个 C 文件（SSE/NEON 向量化） |
| 我们的承载 | **Rust 原生内核**：`std::simd` / `wide` 向量化 + **`rayon` 多线程** + 零拷贝内存映射；像素级合成走 **WebGPU compute shader（WGSL）** |

> **为什么不一定用 WASM**：Tauri 下我们**有原生进程**，Rust 内核直接编译为机器码，比 WASM 更快、更省体积。仅在「必须在前端线程同步执行的小算子」场景才考虑 WASM。

### 5.4 实际采用的库清单（含许可合规）

| 用途 | 库 | 语言 | 许可 | 注意 |
|------|----|------|------|------|
| 图像编解码（主力） | **`image`** crate | Rust | MIT / Apache-2.0 | PNG/JPEG/WebP/GIF/BMP/TIFF/ICO 一站式 |
| HEIC / HEIF | **`libheif-rs`**（libheif） | Rust/C | **LGPL-3.0** | ⚠️ 需 libheif ≥ 1.23.1（≤1.23.0 有 CVE-2026-62291） |
| RAW 解码 | **`rawler` / `rawloader`** | Rust | MIT（`rawler` LGPL，二选一） | 事实标准是 LibRaw；先自测成熟度 |
| SVG 渲染 | **`resvg` / `usvg`** | Rust | **MPL-2.0** | 纯 Rust，正确度高，**无需 WASM** |
| PSD 读取 | **`psd`** crate | Rust | MIT | 常用子集读取；**写入需自研补齐** |

## 六、技术架构

### 6.0 体积预算（≤100MB 红线怎么落地）

> **硬指标**：Windows 安装包（`.exe`）≤ **100MB**；绿色版解压目录 ≤ **100MB**。**不含 WebView2 运行时**（系统组件，按需引导安装）。目标值仍尽量压低到 **10–20MB**，100MB 只作为**不可逾越的上限**。

| 组成 | 预估体积 | 说明 |
|------|---------|------|
| Rust 核心二进制（release + LTO + strip） | 6–12 MB | 编解码 / 内核 / IPC / 工程格式 |
| 前端产物（React + 应用代码，未压缩） | 2–4 MB | 内嵌进二进制或随包分发 |
| 图标 / 资源 / 中文本地化文本 | 1–2 MB | |
| WebView2 运行时 | **0 MB（不打包）** | 系统组件；Win11 与多数 Win10 已预装 |
| **安装包（NSIS 压缩后）** | **10–20 MB** | ✅ 目标区间 |
| **上限（红线）** | **≤ 100 MB** | 硬性上限，**CI 每版自动校验体积，超标即失败** |

> **为什么仍选 Tauri 而不是 Electron**：Electron 必须捆绑整个 Chromium（+ Node 运行时），**空壳打包即 60MB+**；虽未触及 100MB 上限，但启动慢、内存高、更新包大。Tauri 复用系统 WebView2，体积与性能都更优，故仍为首选。

### 6.1 选型总览

| 层 | 选型 | 理由 |
|----|------|------|
| **桌面外壳** | **Tauri v2** | 复用系统 WebView2，安装包可压到 8–15MB；Rust 内核适合图像计算 |
| **界面** | **TypeScript + React + Vite** | 复杂面板组件化省心；热更新开发体验好 |
| **渲染引擎** | **WebGPU 优先，WebGL2 回退** | 图层合成、混合模式、调整、滤镜走 **GPU shader**，这是达到 PS 级流畅度的关键 |
| **矢量 / 文字** | **`resvg`（Rust）/ WebView2 画布** | 复杂路径与排版有工业级实现可用 |
| **重计算** | **Rust 原生内核 + `rayon`** | 内容识别填充、抠图、PSD/RAW 解析、色彩转换走 Rust 多线程，主线程不卡 |
| **AI 推理** | **（无）** | 本项目不含 AI，不引入任何推理运行时 |
| **状态** | **Zustand + Immer** | 文档 / 工具 / 历史栈可预测，撤销重做友好 |

### 6.2 渲染管线（核心中的核心）

```
文档模型（图层树 + 蒙版 + 调整 + 样式 + 变换矩阵）
        │
        ▼
   分块瓦片（Tile）缓存 ── 脏矩形失效，只重画变化的块
        │
        ▼
   GPU 合成（WebGPU）
   ├─ 逐层：变换 → 混合模式（PS 全套）→ 不透明度 → 蒙版 → 剪贴
   ├─ 调整层 / 图层样式：WGSL compute / shader 实时求解
   └─ 视口：缩放 / 平移 / 像素网格
        │
        ▼
     画布显示  ←→  导出 / 保存（Rust 侧按全分辨率重渲染）
```

**关键设计决策：**

- **非破坏优先**：变换存矩阵、调整存参数、文字存文本，**尽量不提前栅格化**（沿用 Compositor `.comp` 的思路）。
- **分块 + 脏矩形**：大文档只重算变化区域。
- **CPU / GPU 各司其职**：能上 GPU 的绝不走 CPU；必须 CPU 的进 **Rust 侧线程池**。
- **精度**：内部按 **16 位/通道** 设计（P2 起），避免多次调整后的色阶断层。

### 6.3 关键子系统

| 子系统 | 要点 |
|--------|------|
| **文档模型** | 图层树、图层类型（像素 / 调整 / 文字 / 形状 / 组 / 智能对象）、蒙版、剪贴关系、混合模式枚举（严格对齐 PS 顺序） |
| **历史栈** | 撤销 / 重做；大操作走「引用 + 差异」而非整体快照 |
| **选区系统** | 位图蒙版（灰度）+ 矢量路径并存；蚂蚁线渲染 |
| **画笔引擎** | GPU 绘制、笔刷间距、压感（数位板，P2）、稳定器平滑 |
| **文字系统** | 编辑态用 DOM 覆盖层（contenteditable）保证输入体验，提交后按 `cosmic-text` / 画布光栅化 |
| **文件 IO** | PNG/JPEG/WebP 走 `image`；HEIC 走 `libheif-rs`；RAW 走 `rawler`；SVG 走 `resvg`；PSD 以 `psd` crate 为底座 + 自研补齐 |
| **色彩管理** | `lcms2` 做 ICC 转换与软打样 |
| **工程格式** | `.strata`：`manifest.json` + `layers/*.png`；**v1 即引入版本号 + 显式校验 + 往返测试** |

### 6.4 Tauri 分层

```
src-tauri（Rust 主进程）
  窗口 / 菜单 / 原生对话框 / 文件关联 / 自动更新 / 崩溃恢复
  + 图像内核（编解码 / 滤镜 / 合成 / 导出）
      │  Tauri IPC（命令 + 事件，白名单式，最小暴露）
src（WebView2 前端）
  React UI + WebGPU 引擎 + Worker 池
```

> **安全**：IPC 走 **命令白名单**，前端不直接触达文件系统与任意系统调用；`tauri.conf.json` 显式声明 `allowlist`。

### 6.5 笔迹延迟方案（绘画线的关键验证项）

原生窗口下 PS / Krita 的笔迹延迟约 **5–10ms**；WebView2 + WebGPU 路径受合成与事件回传影响，预估落在 **15–25ms**，即慢 1–2 帧。该水平与 Figma 一类 Web 应用相当，可用于绘画，但需在 M2 用真实数位板实测确认。

三层缓解，自上而下逐级兜底：

1. **采集层**：`pointerrawupdate` 事件配合 `getCoalescedEvents()`，一次取回自上次绘制以来的全部触点，避免浏览器合帧丢点。
2. **绘制层**：笔迹先画在 **GPU 覆盖层**，屏幕每帧即时反应；抬笔时把整条笔迹提交到画布图层并进入历史栈，绕开图层重合成带来的回传延迟。
3. **兜底层**：若实测仍不达标，改用**无边框原生 Rust 笔迹窗口**，浮于 WebView 之上，由 Rust 直接接管绘制与合成，抬笔后回传图层。

> **验收动作**：M2 安排半天延迟基准测试（数位板绘制 + 录屏对照），取得可量化数值后再决定是否启用第三层。

## 七、界面与交互规范（去臃肿）

> **出发点**：PS 功能全但界面臃肿（11 个顶层菜单、面板成堆堆叠），Krita 则把大量控件常驻台面导致拥挤。Strata 的界面目标是**扁平、简约、不显廉价**，同时保留 PS 级工作流。做法是**按需展开**：菜单与面板的深层功能靠唤出，不靠堆叠；工具则相反，直接铺开、随手可点。

### 7.1 四条改造规则

| 项 | 常规做法 | Strata 做法 | 收益 |
|----|---------|------------|------|
| **工具** | 30+ 图标铺满工具轨 | **保留 30+ 工具直接可见**，统一图标风格与视觉重量，靠形状与含义相互区分；按钮维持常规尺寸，不放大图标、不加过大间距 | 工具一眼可见、随手可点，不必逐层展开找工具 |
| **菜单** | 11 个顶层菜单（文件 / 编辑 / 图像 / 图层 / 选择 / 滤镜 …） | 菜单入口保留，另配一个**命令面板（`Ctrl+K`）**，搜索命令 / 滤镜 / 功能直达 | 常用命令一键命中，不必记菜单层级 |
| **面板** | 颜色 / 色板 / 图层 / 通道 / 路径 常驻并堆叠 | 右侧**单列标签**（图层 / 通道 / 路径），其余（颜色、调整、历史、笔刷库、属性）改为**按需呼出**的浮层 | 画布占比提升，面板不再拥挤 |
| **选项条** | 10+ 项参数常驻 | **3 项随工具变化 + 「⋯ 更多」** | 选项条长度恒定，不随工具膨胀 |

### 7.2 保留项

- 多文档标签页（PS 习惯，切换效率高）
- 工作区切换：**修图 / 绘画** 两个预设，切换默认工具与面板露面项
- 状态栏：缩放、文档尺寸、色彩空间、内存占用
- 画布与变换手柄（选区、自由变换 8 手柄）

### 7.3 视觉风格

- 扁平化，不用重阴影与强渐变；统一圆角（8 / 12 / 999）
- 留白充足，间距一致；浅色为默认，深色可切换
- **全中文界面**，无英文硬编码残留
- 品牌紫作为唯一强调色，用于选中态、主按钮与关键标识
- 品牌标识（Logo）为**深灰圆角方块 + 白色 `St` 字标**，素材存放在 `assets/brand/`；原始素材外围带一圈浅蓝底色，生成应用图标时需去掉

### 7.4 一套界面，两个工作区

界面只有一套。修图与绘画共用画布、图层、通道、色彩管线与历史栈；工作区切换只改变**默认工具集**与**面板露面项**。界面组件只维护一套，用户也不必在两套操作习惯间来回适应。

### 7.5 开始页面

桌面端启动后先进入**开始页面**，与 Figma / Blender / Office 一类生产力软件一致。开始页面承担「进入工作前的一次选择」，让用户先完成新建 / 打开 / 导入，再进入编辑界面。

| 区块 | 内容 |
|------|------|
| **新建画布** | 常用预设（1920×1080、1080×1080、A4 300dpi 等）+ 自定义宽高、分辨率、背景色；页面上的主按钮 |
| **最近文件** | 最近打开或保存的 `.strata` 工程与图片，含缩略图、文件名、路径、修改时间；可一键重开或从列表移除 |
| **导入** | 打开本地图片（PNG / JPEG / WebP / TIFF 等）与 `.strata` 工程；支持把文件拖进窗口直接打开 |
| **其它入口** | 打开示例工程、快捷键速览、切换浅色 / 深色主题、关于与版本信息 |

行为约定：

- 首次启动且无历史记录时，最近文件区显示空状态提示与「新建画布」引导，不留空白列表。
- 顶部保留应用标识与主菜单入口（文件 / 编辑 / 帮助），开始页面本身即可完成常用操作。
- 关闭全部文档后回到开始页面，程序不退出；由标签栏或菜单返回开始页面。

> **交付归属**：开始页面属于 **M0** 交付范围；M0 不做正式编辑界面（见 §十）。

## 十、里程碑路线图

| 里程碑 | 目标 | 交付物 | 验收 |
|--------|------|--------|------|
| **M0 · 骨架** | 能启动的入口 | Tauri 窗口 + **开始页面**（最近文件 / 新建画布 / 导入）+ 最小画布（打开 / 导出 PNG） | 双击即开、从开始页进图；**安装包 < 100MB（目标 < 20MB）** |
| **M1 · 可用（P0）** | 能干活的基础版 | 图层 / 画笔 / 选区 / 变换 / 基础调整 / 导出；**编辑界面**按 §七 落地（工具可辨识、命令面板、单列面板） | 完整走通「打开 → 修 → 存」 |
| **M2 · 完整（P1+P2）** | **完整版** | 蒙版 / 调整图层 / 图层样式 / 文字 / 形状 / Camera Raw / PSD 读写 / `.strata` 工程格式；完成笔迹延迟基准测试（见 §6.5） | 对标 Compositor 功能清单，主要项不缺 |
| **M3 · 打磨（P3）** | 发布级 | 性能优化 / 动作 / 脚本 / 快捷键自定义 / 安装包 + 自动更新 | **达到「AI 小方」的完成度** |
| **M4 · 开源发布** | 见人 | GitHub 仓库（全中文 README）+ Release + 网盘分发 | 用户能下载即用 |

> **节奏建议**：M0 → M1 先把「最小可用闭环」打通，尽早能上手摸；再按 M1 → M2 → M3 逐层加厚。**不做一次性大爆炸，每一步都能跑。**

## 十一、性能与验收标准

| 指标 | 目标 |
|------|------|
| **体积** | **安装包 ≤ 100MB（红线）**；目标 10–20MB；CI 每版校验 |
| 冷启动 | ≤ 1.5s（Tauri 无捆绑运行时，天然更快） |
| 打开 4K 图（约 2400 万像素） | ≤ 2s |
| 画笔延迟 | 绘画线目标 ≤ 16ms/帧（肉眼无感）；WebView2 路径预估 15–25ms，M2 实测后决定是否启用原生笔迹窗口（见 §6.5） |
| 图层开关 / 不透明度拖动 | 实时（≥ 60fps，GPU 合成） |
| 20 图层文档缩放 / 平移 | 流畅不掉帧 |
| 内存 | 自适应预算；大文档不 OOM，超出时降级而非崩溃 |
| 崩溃恢复 | 自动保存 + 重启可恢复 |
| **中文化** | 界面 **100% 中文**，无英文硬编码残留 |

## 十二、无 AI 声明与边界（明确写出，避免误解）

> **Strata 不含任何 AI / 机器学习功能。** 这是产品定位的一部分，不是暂缺。

- **不做**：智能抠图、去背景、生成式填充、超分辨率、人脸/物体识别、自然语言改图、任何需要模型推理的功能。
- **不引入**：ONNX Runtime、Windows ML、DirectML、任何模型文件（`.onnx` / `.pt` 等）。
- **不用 AI 的等价替代**（保留的确定性功能）：
  - 「选择主体」→ **魔棒 / 色彩范围 / 快速选择 / 通道法**
  - 「移除背景」→ **色彩范围 + 图层蒙版 + 内容识别填充**
  - 「生成式填充」→ **内容识别填充**（`ContentFill` 式确定性算法）
- **好处**：体积可控（不带模型与推理运行时）、算法可解释、无隐私顾虑、无 GPU 兼容性坑、维护成本低。

## 十三、风险与取舍

| 风险 | 影响 | 应对 |
|------|------|------|
| **体积红线（≤100MB）** | 稍不注意就被依赖撑爆 | 选型即约束；只引入纯 Rust 轻量库；CI **体积门禁**，超标即失败 |
| **PSD 格式极复杂** | 读写兼容度难做满 | 先做「常用子集 + 转换报告」，明确告知哪些可编辑、哪些被栅格化；以 `psd` crate 为底座 + 自研补齐 |
| **WebView2 依赖** | 极老 Win10 可能缺 | 安装包引导安装 WebView2 运行时（体积不计入 100MB 红线） |
| **Web 端性能天花板** | 超大文档可能吃力 | 分块 + 脏矩形 + GPU 合成；关键算子下沉 **Rust 原生多线程** |
| **弱 copyleft 依赖** | 许可合规 | 开源免费项目无压力；README 做**开源许可声明** |
| **RAW / HEIC 解码成熟度** | 依赖第三方解码库 | P2 再上，先覆盖 PNG/JPEG/WebP 主流格式 |
| **WebView2 笔迹延迟** | 绘画线手感可能不达标 | 三层缓解（见 §6.5）；M2 早测，必要时以原生笔迹窗口兜底 |
| **范围蔓延** | 「完整版」变无底洞 | 严格按 P0–P3 分层，每个里程碑可独立交付 |
