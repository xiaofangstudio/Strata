## 一、偏好设置：三个问题（优先，用户直接感知）

### 1.1 窗口「一大一小」

**现象**：切换左侧页签时，弹窗高度忽大忽小。

**已查**：`Preferences.css` 里 `.pref` 其实已经写了 `height: 460px` + 内容区 `overflow-y: auto`，
理论上应该固定。所以问题多半出在**外层 Modal**：Modal 的高度如果是「按内容撑开」，
`.pref` 的 460 只是下限，某些页内容溢出（或某些页根本没内容）就会让 Modal 跟着变。

**动手点**
- 看 `Modal.tsx` 是否对 `maxHeight` 做内容自适应；给偏好设置这种"固定型"弹窗加一个 `fixedHeight` 变体。
- 复现时记录：哪两页之间跳动、差多少 px（明天要一张截图更稳）。

### 1.2 滚轮

**现象**（两种可能，需当场确认）：
- (a) 在偏好设置里滚鼠标，内容**不滚动**；
- (b) 或用户其实想要「滚轮缩放这个窗口」。

**已查**：编辑器视口在 `EditorShell` 里挂了一个 `wheel` 原生监听（`vp.addEventListener("wheel", …)`），
`Ctrl+滚轮` 缩放画布、普通滚轮平移画布，且**没有判断当前是否有弹窗打开**。
如果偏好设置的 DOM 落在视口内部（不是 portal 到 body），滚轮会被视口先吃掉 →
表现为「滚不动」。

**动手点**
- 确认 `Modal` 是否 `createPortal` 到 `body`；若是体内容，改成 portal（`Popover` 已经这么做了）。
- 或者在视口的 wheel 处理里加守卫：`if (document.querySelector("[data-modal-open]")) return;`
  —— 需要 `Modal` 打开时给 body 打标记。
- 若用户本意是「滚轮缩放窗口」，再单独做（`Modal` 加 `resizable` + 记住尺寸）。

### 1.3 「这也不是很偏好设置」

**现状**：19 个页签一长串平铺，语义混杂：

```

光标 透明与色域 单位与标尺 参考线、网格 文字 增强控件 Raw 默认 增效工具 AI 集成
```

「性能 / 暂存盘」是一类**，现在全平铺，找东西要一行行扫。

**动手点（建议分组，仍是两级左侧栏）**

## 二、启动意图要分开：主动开软件 vs 用软件开文件（✅ 已完成）

### 2.1 要区分的是两种"入口"

| 用户怎么进来的 | 期望行为 |
|---|---|
| 点桌面图标 / 开始菜单，**没带文件** | **进欢迎页**（新建设置大小、最近文件、拖入图片） |
| 双击一张 png/jpg，或在资源管理里「用 Strata 打开」 | **直接进编辑器打开那张图**，不经过欢迎页 |
| 双击一个 `.strata` 工程 | **直接进编辑器打开工程**，不经过欢迎页 |
| 软件已开着，又双击一个文件 | 把文件送到**已有窗口**里打开（不再起第二个进程） |

**判定依据只有一条：启动时 argv 里有没有一个「我们能打开的文件路径」。**
有 → 编辑器；没有 → 欢迎页。跟「最近用过什么」「上次开在哪」都无关。

### 2.2 现在的代码为什么做不对

`App.tsx` 的渲染判定是：

```tsx
const doc = activeId === null ? null : docs.find(d => d.id === activeId) ?? null;
if (doc) return <EditorShell … />;
return <StartPage … initialPath={launchPath} />;   // ← 只要还没文档，就一定先渲染欢迎页
```

而「打开启动文件」这件事被塞在 `StartPage` 的 `useEffect` 里（挂载后才 `openPath(initialPath)`）。
于是必然出现：

1. **先渲染欢迎页** → 用户看到欢迎界面；
2. 副作用里才开始解码文件 → 成功后才切到 `EditorShell`；
3. 如果这一步失败（扩展名没匹配、argv 里没有、解码报错），**就永远停在欢迎页**，而且没有报错。

这就是「双击图片进去是欢迎页」的直接原因 —— **不是没打开，是被欢迎页挡在前面了。**

### 2.3 改法：把"启动意图"提到首屏之前判

```
启动
 ├─ 读 argv（Rust initial_open_args）
 ├─ 有可打开的文件路径？
 │    ├─ 是 → 进 booting 态（显示「正在打开 xxx…」），成功 → EditorShell
 │    │        失败 → 明确报错 + 退回欢迎页
 │    └─ 否 → 欢迎页
```

具体动作：

1. **App 增加 `booting` 状态**：`initial_open_args` 还没回来时，首屏渲染一个轻量加载态，
   **不要先渲染 StartPage**（避免闪一下）。
2. **把自动打开从 StartPage 挪到 App**：StartPage 只负责"用户点新建/打开"，
   删掉 `initialPath` 这个 prop 与那个 `launched` ref。
3. **失败要有声**：打不开就 `setError`（现有 Toast/Error 通道），并回到欢迎页。
4. **单实例**：加 `tauri-plugin-single-instance`，在 `on_new_args` 里把新参数转给已有窗口。
   否则用户双击第二个文件会**起第二个 Strata 进程**，两个进程抢同一个 recent 列表。
5. **`fileAssociations` 要补图片扩展名**（这条你已确认要加）：

   ```json
   "fileAssociations": [
     { "ext": ["strata"], "name": "Strata 工程文件", … },
     { "ext": ["png","jpg","jpeg","webp"], "name": "图片", "role": "Editor" }
   ]
   ```

   注意：注册关联 ≠ 抢默认。安装时只登记"我能开"，是否设成默认仍由用户在系统里选。

### 2.4 排查顺序（如果改完还不对）

| # | 查什么 | 判据 |
|---|---|---|
| 1 | argv 里到底有没有路径 | 临时在 `initial_open_args` 里 `eprintln!("{:?}", args)` |
| 2 | 扩展名是否在 `IMAGE_EXTENSIONS` 里 | `src/engine/image.ts` 第 7 行 |
| 3 | 带空格/大写的路径（`extOf` 是否小写化） | 补单测：`"C:////A B////X.PNG"` |
| 4 | 是否起了第二进程 | 任务管理器看 Strata 进程数 |
| 5 | 安装包是否真的写了关联 | 注册表 `HKCU\\Software\\Classes\\SystemFileAssociations\\.png\\OpenWithProgids` |
