# 小方工作室 · 工具生态链规划

> **小方工作室 · 出品** ｜ 文档版本 `v0.4` ｜ 2026-10-05 ｜ 状态：**生态骨架已定（重点三位：Strata · ReelForge · FangKit），并补全工具链其余位次与生态链下载器 FangBox**

> **本版范围**：这份文档只管「工作室要做一个什么样的软件家族」，不展开任何单个产品的功能细节。单个产品的规划见各自的立项规划书（如 Strata 见 `立项规划书.md`）。

---

## 一、这份文档要回答什么

小方工作室的目标不是做一款软件，而是做一整套互相配合的工具链。这条路线下，作品之间要能共享底座、共享交互习惯、共享配色与界面语言，让人用熟一个就能上手下一个。同时它也必须现实：生态链不能同时开工，必须排先后、标难度、留后手。本文档给出产品线的骨架、先后顺序与依赖关系，作为后续逐个立项的入口。

---

## 二、产品线总览

| 位次 | 产品 | 做什么 | 技术底座 | 难度 | 状态 |
|------|------|--------|----------|------|------|
| ① | **Strata** | 修图 / 绘画（对标 Photoshop，全功能） | Tauri v2 + React + WebGPU + Rust | 高 | **进行中 · 当前唯一焦点** |
| ② | **ReelForge** | 视频剪辑 / 合成（Clypra 与 Gaffer 两个方向整合） | 待定（Clypra 同栈可承接） | 极高 | **预定 · 以后做** |
| ③ | **FangKit** | 全家族共享的原生底座与界面组件库 | Rust + Web 组件 | 中 | **预定 · 第二个产品前抽取** |
| ④ | **FangBox** | 生态链下载器 / 启动器（对标 JetBrains Toolbox） | Tauri v2 + React | 低 | **近期 · 明天做** |
| ⑤ | **LineForge** | 矢量绘图与排版（对标 Illustrator / InDesign） | 待定 | 高 | 构想 · 未立项 |
| ⑥ | **WaveCraft** | 音频编辑与处理（对标 Audition） | 待定 | 中 | 构想 · 未立项 |
| ⑦ | **ScreenForge** | 截图 / 录屏 / 标注 | 待定 | 低 | 构想 · 未立项 |
| ⑧ | **AssetForge** | 素材库与资源管理（对标 Bridge，DAM） | 待定 | 中 | 构想 · 未立项 |
| ⑨ | **FormatForge** | 格式批量转换与导出打包 | 待定 | 低 | 构想 · 未立项 |

> **一句话记住**：`先把 Strata 做完，ReelForge 和共享底座先记在案上，不并行、不提前动工；FangBox 体量小，可与 Strata 并行先做。`

**品牌命名逻辑。** 九个位次按职能分三族。基础设施族以 `Fang` 开头：**FangKit**（底座）、**FangBox**（下载器）。创作工具族统一以 `-Forge` 收尾，取「锻造」之意——**ReelForge**（影像）、**LineForge**（矢量线条）、**ScreenForge**（屏幕捕获）、**AssetForge**（素材）、**FormatForge**（格式）。两款旗舰单独命名：**Strata** 取「地层」，对应图层叠加这一核心模型；**WaveCraft** 取「波形 + 工艺」。这样一眼就能分出「这是基础设施」还是「这是干活用的工具」。

**关于第二个产品的名字。** 它定名 **ReelForge**。名字由两个词拼成：`reel` 是影像工业里最本源的物件，一卷胶片即一个 reel，它同时是剪辑与蒙太奇的代名词；`forge` 取「锻造」之意，对应这个产品把零散素材、时间线与节点图打成一件成品的工作方式。合起来就是「把胶片盘锻造成作品的工坊」，正好盖住它「时间线剪辑 + 节点合成」的复合定位。ReelForge 在影像软件领域未检索到同名产品，可以放心用它做 logo 与视觉识别。

**关于其余名字。** ④～⑨ 为新补全的位次，命名时已逐个检索回避同名产品（`FangHub`、`ToolForge`、`Vekta`、`Auralis` 等均已被占用，故弃用）。这些名字目前是候选，正式立项时再复核商标与域名可用性。

## 三、产品一 · Strata（当前焦点）

Strata 是小方工作室的第一款正式产品，也是整条生态链的地基。定位为 Windows 优先、全中文、永久免费开源（MIT）的 Photoshop 平替，修图与绘画并列为一级能力。它承担两个额外角色：一是验证 Tauri v2 + WebGPU + Rust 这套技术栈在桌面端的实际手感（尤其是笔迹延迟），二是沉淀出可复用给后续产品的交互习惯与界面语言。详细规格以 `立项规划书.md` 为准，本文档不重复。

---

## 四、产品二 · ReelForge（Clypra + Gaffer 整合）

这是工作室预定的第二款重磅产品，方向是把两个现成开源项目的能力整合进同一个剪辑软件，而不是从零造轮子。两款参照物的定位差异很大，整合难度也主要来自这里。

**Clypra** 是开源桌面视频编辑器，技术栈为 Tauri 2 + React 19 + TypeScript + Tailwind CSS 4 + Vite 7，媒体处理走 FFmpeg CLI，MIT 协议 [$TRAE_REF](https://github.com/AIEraDev/Clypra)。它提供多轨非线性时间线、帧精确剪辑、音频波形与 FFmpeg 后端导出 [$TRAE_REF](https://www.x-cmd.com/install/clypra/)。关键在于它和 Strata **用的是同一套 Tauri + React + TypeScript 栈**，这意味着底座、界面组件、构建流程都有机会直接复用，是整条生态链里最自然的一块拼图。

**Gaffer** 是免费开源的节点式 VFX 应用，面向 look development、灯光与合成，采用 BSD-3-Clause 协议，由 Image Engine 主导，支持 Python 与 OSL 脚本、C++ / Python API，底层是多线程延迟求值引擎 [$TRAE_REF](https://www.gafferhq.org/)[$TRAE_REF](https://alternativeto.net/software/gaffer/about/)。它的价值在于节点图与合成管线，正好补上 Clypra 偏时间线剪辑、缺少节点式合成的缺口。

**整合的方向**：以 Clypra 的时间线剪辑为主体骨架，把 Gaffer 的节点式合成思路引入，做成「剪辑 + 节点合成」一体的工作台。这里要说清楚难度来源：Gaffer 是 C++ / Python 的大型桌面应用，与 Tauri + Web 前端是两个世界，不能直接拼装，真正可行的是**借鉴其节点图模型与合成管线的设计思路，在自家技术栈内重写**，而不是把 Gaffer 嵌进来。因此这项工作排在 Strata 完成之后，且需要单独立项、单独评估。

| 维度 | Clypra | Gaffer |
|------|--------|--------|
| 定位 | 时间线剪辑 | 节点式 VFX / 合成 |
| 技术栈 | Tauri 2 + React + TS + FFmpeg | C++ / Python + OSL |
| 协议 | MIT | BSD-3-Clause |
| 与 Strata 的关系 | **同栈，可复用底座** | 思路参照，需重写 |

## 五、产品三 · FangKit（共享底座）

当第二个产品真正开工时，工作室必须先做一件前置工作：把 Strata 里可复用的部分抽成共享底座，而不是复制粘贴。这块底座暂定名 **FangKit**，覆盖原生层封装、界面组件库、配色与视觉规范、文档模型与撤销系统、文件 IO 与偏好设置等一类跨产品通用能力。

FangKit 的抽取时机要卡准：太早会把还没定型的接口固化成包袱，太晚则会在第二个产品里重复造一遍。可行的做法是 Strata 进行到中后段、界面与内核相对稳定时，再回头做抽取与沉淀。

## 六、产品四 · FangBox（生态链下载器）

FangBox 是整条工具链的入口：一个桌面应用，把工作室全部软件收在一处，负责下载、查看版本与手动更新，形态对标 JetBrains Toolbox。它排在最前面做，理由有三：体量小、技术上没有硬难点；能让生态链立刻「可被下载」，先有入口；此后每新增一个软件，只需往目录里加一条记录，边际成本极低。

**目录页。** 列出工作室全部软件（Strata、ReelForge、LineForge…），每个条目显示图标、名称、一句话简介、本机已装版本与最新版本。未安装的显示「下载」，已安装的显示「打开 / 重装 / 卸载」。

**版本检测。** 联网查两处来源，取较高者：一是官网的版本清单（一个约定的 JSON，例如 `官网/api/products.json`）；二是 GitHub Releases API（`api.github.com/repos/xiaofangstudio/<仓库>/releases`）。两处对不上时以版本号较高者为准，并在条目上标明来源。

**双渠道下载。** 每个软件提供两个入口——「官网下载（MSI，推荐）」与「GitHub 下载（免安装包）」，由用户自选。两个渠道的版本号保持对齐。

**只手动，不自动。** 检测到新版本只做提示，必须用户点按钮才下载；**永不后台自动更新、永不静默替换**。本地已装软件不去动它，用户不点就不变。下载完成后交给系统处理（MSI 双击安装）或落到用户指定目录，不做强制接管。

**分发与打包。** FangBox 只上官网，**不进 GitHub**（体量小、无技术含量，不必占一个仓库）。它自身用 Tauri v2 的 MSI 目标（`tauri.conf.json` 里 `"targets": "msi"`，走 WiX）打包成 MSI，官网提供 MSI 安装包。它下载的那些软件同理：官网渠道给 MSI，GitHub 渠道给免安装包。

## 七、推进顺序与依赖

1. **Strata 优先，且单独推进。** 在 Strata 达到可用版本之前，不启动剪辑软件的任何工程动作，避免战线过长。
2. **FangBox 先落地。** 它体量小、依赖轻，可与 Strata 并行先做，让生态链先有一个可下载的入口。
3. **Strata 沉淀 → FangKit 抽取。** 底座从真实产品里长出来，而非凭空设计。
4. **FangKit 就位 → 剪辑软件立项。** 剪辑软件复用底座，把精力集中在时间线与节点合成这类真正的难点上。
5. **不做并行开发。** 重产品线一次只开一条；一人 / 小体量工作室同时开两条重产品线，结果是两条都做不完。

## 八、风险与取舍

| 风险 | 影响 | 应对 |
|------|------|------|
| **战线过长** | 生态链一起上，哪个都做不完 | 严格串行；Strata 未完成前不碰剪辑软件 |
| **Gaffer 整合错判** | 以为能拼装，实际是两个技术世界 | 明确定位为「思路参照 + 自研重写」，不承诺直接集成 |
| **底座抽取过早** | 把未定型接口固化成包袱 | 卡在 Strata 中后段再抽 FangKit |
| **命名与品牌割裂** | 产品各说各话 | 统一视觉规范与交互习惯；按「Fang = 基础设施 / -Forge = 创作工具」分族命名 |
| **协议合规** | 复用开源项目带来许可风险 | 只用 MIT / BSD 这类宽松许可的参照物；Strata 自身保持 MIT |
| **双渠道版本错位** | 官网与 GitHub 版本号不一致，用户无所适从 | FangBox 做唯一的版本判断入口，两处版本号对齐发布 |
