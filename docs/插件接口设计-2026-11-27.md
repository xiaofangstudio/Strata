# Strata 插件接口设计（v0 草案 → v1 沙箱 → v2 UI 扩展）

> 现状：Strata 完全没有插件的外接接口——第三方无法在不动源码的前提下给
> Strata 加功能。本文档定接口形状与三段路线；v0 的宿主内核
> （`core/pluginHost.ts`，manifest 校验 + 动作白名单）与单测本轮已落地。

## 0. 设计原则

1. **能力白名单制**：插件能做什么在 manifest 里声明，宿主逐条校验；没有
   「随便 import 一个内部模块」的通道。
2. **破坏性动作显式授权**：写文件、覆盖图层像素属于危险能力，manifest 声明
   `permissions`，宿主在执行前提示一次（v0 直接拒没有声明的能力）。
3. **声明式先行，代码沙箱后行**：v0 用 JSON 描述动作序列（ Actions 超集），
   不执行第三方代码——在沙箱模型（v1）没建好之前，不提供能执行任意 JS 的
   「假插件接口」。
4. **文档模型稳定优先**：插件操作的是文档命令（与 MCP 工具同一套语义），
   不直接摸内部数据结构，这样宿主升级不破坏旧插件。

## 1. Manifest（v0）

```jsonc
{
  "manifest": "strata-plugin",
  "version": 1,
  "id": "com.example.thumbnailer",
  "name": "批量缩略图",
  "author": "…",
  "pluginVersion": "1.0.0",
  "permissions": ["document.read", "document.modify", "file.write"],
  "menus": [
    { "id": "make-64", "label": "生成 64px 缩略图", "actions": [ … ] }
  ]
}
```

字段校验（`core/pluginHost.ts::parseManifest`）：id 必须是反向域名；
`permissions` 里的每个值必须在能力白名单内；`menus[].actions` 每条动作的
`command` 必须在命令白名单内、参数类型逐条对齐。坏 manifest 整体拒绝并给
中文错误，不做静默修正。

## 2. 能力白名单（v0）

| 权限 | 允许的动作 |
|---|---|
| `document.read` | 读文档元信息（尺寸/图层数/活动层名） |
| `document.modify` | 缩放画布、加调整层、栅格化、翻转/整倍旋转 |
| `file.write` | 导出 PNG 到用户指定路径（每次经系统保存框，插件拿不到静默写盘） |

命令白名单与 MCP 工具同源对齐（`strata_doc_*` 的子集），宿主执行动作 =
调用文档层现有纯函数/引擎函数，不走字符串 eval。

## 3. 生命周期（v0）

加载（用户从菜单选 `.json` 清单文件）→ 校验 → 动作注入「插件」菜单区 →
会话内可用 → 重启后需重新加载（v0 不做持久安装，避免「装了什么不知道」）。

## 4. v1：JS 沙箱（动作表达不了的逻辑）

- 插件代码跑在 **Worker**（无 DOM）里，宿主与 worker 之间用 postMessage +
  结构化克隆传「文档命令请求/响应」；插件拿不到 canvas 与文件系统句柄。
- 权限模型不变：manifest 声明 → 宿主执行 → 结果回传。
- 计时器/循环防护：单次动作调用超时 10s，超时杀 worker。

## 5. v2：UI 扩展

- 插件可声明面板（dock 区一个 iframe 面板），与宿主经 postMessage 通信。
- 分发：本地文件夹 + 手动加载为主，后续再考虑市场（明确：不做自动更新
  通道，防止供应链投毒）。

## 6. 与其它外接接口的边界

- MCP：给 AI 用的工具面（进程外）；插件 API：给人用的扩展面（进程内）。
  两者共用文档命令语义，但权限模型独立。
- 脚本事件管理器：已有的内部自动化通道，保持不动；插件不经过它。
