## 三、六项的修复方案

### 1. PSD 写侧补全（🟡→✅，成本最低感知最强）

**方案**：继续用 ag-psd（成熟、纯 TS、已在用），不换自研。

- 组写回：Strata 组 → ag-psd `Layer{opened:true, children:[...]}`，保留名称/不透明度/可见性/混合模式（对齐 PhotoCraft `GroupSpec` 的字段集：名称、混合、不透明度、可见性、展开状态）。
- 文字层写回：ag-psd 原生支持写 text layer（`text:{...}`）——把 Strata TextSettings 映射过去（字体/字号/颜色/对齐/字距），变形文字烤成像素层并注明。
- 调整层：带蒙版的烤成「像素层+蒙版」；纯调整写 ag-psd 的 adjustment layer 类型（brightnessEvent/levels/curves 里能映射的），映射不了的降级为烤平并弹提示。
- 蒙版写出：像素层自带蒙版的写 `Layer.mask`（ag-psd 支持）。
- 验收：用 Photoshop 打开 Strata 导出的 PSD，组/文字/可见性/不透明度/蒙版全部正确分层；再用 Strata 重新读回一致（往返测试）。

### 2. 数位板补全（🟡→✅，纯前端零体积）

**方案**：Pointer Events 已是 Windows 数位板（Windows Ink）的标准入口，WebView2 全量上报，不需要也不应该引入 crate（PhotoCraft 的 tablet crate 在 Windows 上同样没有实现）。

- tilt/rotation：`ev.tiltX/tiltY` → 换算笔尖倾角与方位角 → 传入 paint.ts 的笔刷模型：倾斜时椭圆 stamp 依据倾角压扁+旋转（对齐其 `Sample{pressure,tilt_x,tilt_y,rotation,eraser}` 事件字段语义）。
- 擦除笔端：`ev.buttons & 32`（eraser button）或笔具切换 → 自动临时切到橡皮擦（PhotoCraft 同语义）。
- OptionsBar 增加压感/倾斜的启用开关与强度映射曲线。
- 验收：真实数位板（或 Windows Ink 模拟）画线，倾斜能改变笔触形状，翻笔擦除生效。

### 3. HEIC/HEIF 解码（❌→✅）

**方案**（按优先级核许可与体积后二选一）：
1. `heic-rs`（纯 Rust，PhotoCraft 的 heif crate 就是它的 thin wrapper）——加 Tauri 命令 `decode_heic(path) -> {width,height,rgba}`，前端走现有 docFromBitmap。
2. 兜底：Windows 系统解码器（WIC + HEIF Image Extensions，`windows` crate，零体积，但要求用户装了系统扩展）。

- 同时进打开过滤器与导出决策（写侧 HEIC 编码器生态弱，先只做读，导出菜单标注「不支持」）。
- 验收：打开一张 .heic 照片成功建文档；无扩展/损坏文件给中文报错。

### 4. RAW 解码（❌→✅，最大块）

**方案**（按项目规则先移植 PhotoCraft）：
1. 首选：**整体移植 `photocraft-raw`**（纯 Rust：DNG/CR2/TIFF-EP，依赖 zune-jpeg/jxl-oxide，MIT/Apache）——把该 crate 源码并入我们的 workspace 或 src-tauri，文件头保留来源声明，改名为 `strata-raw`。CR3/NEF/ARW 等若其不支持，看其 TIFF/EP 基座能否顺带覆盖，覆盖不了的列进「已知不支持」清单，不硬造。
2. 备选：`rawler`（纯 Rust，注意核 LGPL 与 MSRV）。

- Tauri 命令 `decode_raw(path, {tonemap})`： Demosaic（其内置算法）→ 8bit RGBA → 前端建文档；HDR 高光按曝光 tonemap（复用 previewTone 思路）。
- 打开过滤器加 cr2/cr3/dng/nef/arw 等；EXIF 方向读取顺带处理。
- 体积预估：+3~6MB，红线内 ✅。
- 验收：各格式样张打开即得正确色彩的可编辑文档（对拍 FastRawViewer/IRIS 截图目检）。

### 5. 完整色彩管理 CMS（🟡→✅）

**方案**：移植 `photocraft-cms`（纯 Rust：ICC v2/v4 profile 解析与写入、transform、rendering intents、黑点补偿，MIT/Apache）为 Rust 侧命令，替换我们 colorProfile.ts 的矩阵近似为「ICC profile 存在时走真 transform，否则退回矩阵」。

- Tauri 命令：`cms_transform(pixels, srcProfile, dstProfile, intent, bpc)` + `cms_read_profile(path)`（读嵌入 ICC）。
- 应用内升级：
  - 打开 PNG/JPEG 时读嵌入 ICC 并标记文档 profile（当前只认 sRGB）；
  - 「转换为配置文件」走真 transform + 四种 rendering intent 可选；
  - **软打样**：以输出 profile + intent 做 proof 预览（校样颜色），超色域像素标灰/高亮（ gamut warning ）；
  - 显示侧：monitor profile 读取可后置（Windows 系统级，成本高，先不做，文档里注明）。
- 验收：同一张 p3 图在 sRGB 软打样下色域警告位置与 Photoshop 目检一致；adobe-rgb↔srgb 往返数值误差 < 阈值（写单测）。

### 6. GPU 加速（❌→✅，最后做，工程量最大）

**方案**：前端 **WebGPU**（Tauri WebView2 基于 Chromium，原生支持 `navigator.gpu`），照搬 PhotoCraft gpu crate 的架构——`Kernel` 抽象 + WGSL 逐像素管线（其 compose.wgsl 语义：textureLoad 读输入、effect 走 fragment pass、结果与 CPU 合成一致）：

- `shaders/` 占位目录启用：先写 `compose.wgsl`（图层合成：normal/multiply/screen/overlay…全套 BlendId）+ `adjust.wgsl`（56 参数调整算子）。
- 设备探测：无 WebGPU 时静默回退现有 Canvas2D 路径（双路径共存，结果一致性用像素级单测钉住）。
- 首批加速点（收益最大）：图层合成 flatten、调色台实时预览、滤镜预览。画笔 stamp 后置。
- 明确不做：不引 wgpu/Rust 侧 GPU（跨 WebView 回传纹理得不偿失）。
- 验收：大文档（6000×4000、30 层）flatten 耗时对比 CPU 有数量级提升；GPU/CPU 两条路径输出像素一致（容差内）。

## 四、实施顺序与依赖

| 顺序 | 项 | 理由 |
|---|---|---|
| 1 | PSD 写侧补全 | 纯 TS、零体积、当天可完成 |
| 2 | 数位板 tilt/eraser | 纯 TS、零体积 |
| 3 | HEIC 解码 | 小 crate、打通「Rust 命令→前端建文档」管线，为 RAW 铺路 |
| 4 | RAW 解码 | 复用第 3 步管线；移植 photocraft-raw 工作量最大 |
| 5 | CMS | Rust 侧第二个大件，依赖「读嵌入 profile」与第 4 步同管线 |
| 6 | GPU WebGPU | 独立 track，不阻塞上面任何项，时间不够顺延 |

**每周收尾硬指标**：`tsc` 0 错、vitest 全绿（每项配单测）、`cargo check` 0 错、
体积不破 100MB、MSRV 不高于 1.77、发布走 `npx tauri build`。

## 五、风险与红线

1. **许可证**：移植 photocraft-raw / photocraft-cms 必须保留 MIT/Apache 版权头（回收说明已有此约定）；heic-rs / rawler 许可证在 `cargo add --dry-run` 时一并核对，LGPL 需报用户决策。
2. **体积**：RAW + CMS + HEIC 预计共 +6~10MB，安全；任何要拉 C++ 构建的方案（libraw、libheif 官方绑定）直接否决。
3. **MSRV**：wgpu 30 / 新版 crate 可能顶高 rust-version，dry-run 先行，顶高就锁旧版。
4. **PhotoCraft 的 tablet crate 无 Windows 实现**：不要照抄它的数位板路线，我们走 Pointer Events（更贴合 Tauri 架构）。
