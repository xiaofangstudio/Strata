## 0. 先回答「难度几星」

如果做出 Strata 现在这个程度是 **10 星**，把下面这些全部加上 ≈ **15～16 星**——相当于把 Strata 的一半再重做一遍。明细（增量按十星基准算）：

| 项 | 增量 | 为什么 |
|---|---|---|
| 16bit / 32bit / CMYK 真管线 | **+2** | 整条像素管线现在钉死在 8bit RGBA（`Uint8ClampedArray` / `ImageData`），文档模型连 `depth` 字段都没有。这不是加功能，是换地基：渲染、滤镜、混合、导出几百处都要跟着改 |
| PSD 智能对象往返 | +0.5～1 | SoLd/PlLd 解析 + 嵌套工程往返 + 非破坏编辑；读侧先做到「往返不丢」，写侧可分步 |
| GPU 全通路 | +1 | WGSL 底子已有（blend/adjust/compose），缺的是把它接进主合成路径 + 一致的降级策略 |
| 真 RAW 显影 | +0.5～1 | strata_raw 能解码，缺「显影链」：白平衡/曝光/曲线直接作用在线性数据上，而不是先压到 8bit 再调 |
| 插件外接接口 | +1 | API 设计 + 沙箱 + 生命周期 + 文档，做小容易做对难 |
| MCP capabilities 对账 + 版本 | +0.25 | 纯工程纪律，没有技术难度 |
| 右键 / 作用域逐处对齐 PS | +0.5 | 单点都简单，量大且要一张一张功能过 |

**关键判断：16bit 是杠杆点。** 它决定之后每一行像素代码的写法。每多拖一天，「8bit 假设」就往新代码里多渗透一层，成本只增不减——所以明天只要动得了，先做它的架构决策和最小闭环，而不是先挑好做的做。

### P1 16bit/32bit 架构决策 + 最小读写闭环（明天最重）
1. **先决策后动手**：`StrataDoc` 增加 `depth: 8 | 16 | 32`；存储表示选型（A：surface 继续画布 + 16bit 走 ImageData/Float32 旁路；B：全管线换 Float32 缓冲）。按现在代码形态，先走 A 的**双轨制**：IO 层真 16/32bit，编辑层 8bit 显示 + 高位数据保底，把「读进来降 8bit」明确成可撤的架构过渡，不做假 16bit。
2. TIFF 16bit 读写：读侧多通道解码 + 写侧 16bit 落盘（灰度 16 / RGB 16）。
3. PNG 16bit 读入不再压 8bit 丢数据（至少保留原始值在旁路通道）。
4. EXR 32bit float 通路核对（已有 OpenEXR crate，确认读入后到文档的量化路径）。
5. CMYK：TIFF/PSD 的 CMYK 先「正确读 → ICC 转 RGB 显示 → 保留原始 CMYK 数据供导出」，输出 CMYK TIFF 放 P2 之后再做。
- 开源参考：Rust `tiff` crate（16bit 多页）、`image` crate（PNG16）、已有 `openexr`；管线模型对照 ImageMagick HDRI（Q16/Q32）与 Krita 的深度架构（只看思路不抄 GPL 代码）。

### P2 PSD 智能对象：读侧往返不丢
1. 按 Adobe《Photoshop File Formats Specification》解析 `SoLd` / `PlLd`：识别智能对象层、提取嵌套文档/原始像素、关联 `layer.smart` 已有字段。
2. 读入策略：智能对象层标 `smart` 并保留原始像素（`.strata` 已有 smart data URL 位），栅格视图给合成结果；写回 PSD 时至少回写原始像素块，保证「开→存→再开」不丢。
3. 参考：`psd-tools`（Python，开源 PSD 行为金标准）做往返对照；Photopea 的 smart object 处理方式。
4. 验收：构造含智能对象的测试 PSD，往返后像素/图层树逐位比对。
